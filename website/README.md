# 샤벳 홈페이지

## 현재 상태

운영 봇에서 홈페이지가 실행 중이며 SSH 터널을 통한 Discord 로그인, 관리자 서버 목록, 실제 채널·설정 조회를 확인했습니다. 설정 저장 기능은 2026-09-15 커밋 `a88a7bd`로 배포했습니다. 공개 주소 준비 코드 `17145a0`도 반영했고, 최종 서버 관련 검사 65개·재시작·Discord 재접속·홈페이지 응답을 확인했습니다. 운영자 재로그인 후 실제 채널 저장 검증은 아직 남아 있습니다.

- `#account`: Discord 로그인과 실제 서버·채널 설정 화면
- `#dashboard`: 실제 설정인 `#account`로 연결합니다. 상단 대시보드 메뉴에서도 같은 화면이 열립니다.
- `#preview`: 가상 서버·채널을 사용하는 별도 디자인 시안. 저장해도 운영에는 반영되지 않으며 일반 메뉴에서는 연결하지 않습니다.
- 주소에 화면을 지정하지 않으면 샤벳 소개를 표시합니다.
- 소개·명령어 안내: 기존 정적 페이지. 명령어 이미지는 사용자 촬영본을 추가할 자리입니다.

## 설정 저장

공개 업데이트 내역은 `#updates`에서 로그인 없이 확인합니다. `website/dist/updates.json`에 날짜(`date`), 제목(`title`), 변경 목록(`items`)을 최신순으로 추가합니다. 실제 배포한 사용자 영향만 기록하고 내부 경로·서버 정보·개인정보·미배포 계획은 넣지 않습니다. 별도 웹 편집기는 없으며 코드 배포와 함께 갱신합니다.

텍스트 채널에서는 공지·미라클 타임·캐시이동·우르스·썬데이 당일/목록·서버 오픈·환율 기록을 설정합니다. 서버 오픈을 켤 때는 멘션 역할이 필수이며 역할만 변경할 수도 있습니다. 저장하는 순간 역할을 멘션하지는 않습니다.

음성 채널에서는 시간·UTC·환율 표시를 설정합니다. 같은 채널에는 한 종류만 켤 수 있습니다. 기존 종류를 끈 다음 다른 종류를 켭니다. 큐브세일은 기존 봇도 채널 예약만 지원하므로 웹 변경 목록에서는 제외했습니다.

각 기능 카드 안에서 받을 채널·ON/OFF·필요한 역할을 고르고 `저장`을 한 번 누르면 바로 적용됩니다. 추가 확인 단계는 없습니다. 현재 사용 중인 채널과 즉시 동작 안내를 항목별로 표시합니다. 선택한 채널의 설정만 변경하며, 다른 채널이나 다른 카드의 미저장 입력은 유지합니다.

| 종류 | 켤 때 | 끌 때 |
| --- | --- | --- |
| 썬데이 당일 | 현재 진행 중인 일정이 있으면 바로 전송 | 해당 채널의 기존 당일 메시지 삭제 |
| 썬데이 목록 | 저장된 일정이 있으면 바로 전송 | 이후 알림 중단 |
| 환율 기록 | 현재 환율을 바로 전송 | 이후 기록 알림 중단 |
| 시간·UTC·환율 표시 | 음성 채널 이름 변경·자동 갱신 | 자동 갱신 중단, 이전 이름은 복원하지 않음 |
| 나머지 알림 | 다음 알림부터 적용 | 이후 알림 중단 |

웹 API는 매 요청에서 Discord 관리자 권한, Origin·CSRF, 채널 소속·종류와 봇 권한을 검사합니다. 이전 ON/OFF 및 서버 오픈의 이전 역할을 비교해 다른 곳에서 바뀐 설정을 덮어쓰지 않습니다.

홈페이지와 `/채널설정`은 봇의 `apply_channel_setting`을 공유합니다. 설정 저장끼리는 순서를 지키고, 상태 파일은 완성된 임시 파일로 교체합니다. 저장 실패 시 메모리를 복원하며 즉시 메시지를 보내지 않습니다. 저장 후 즉시 전송·이름 변경·후속 기록만 실패하면 설정 저장과 구분한 경고를 표시합니다. 같은 설정을 다시 저장해 즉시 메시지를 반복 전송하지 않습니다. 응답이 끊긴 경우 현재 상태를 다시 조회합니다.

## 실행

정적 디자인 시안만 보려면 프로젝트 루트에서 실행합니다.

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory website/dist
```

주소: http://127.0.0.1:8765/

로그인만 별도로 개발할 때는 다음 명령을 사용합니다. 실행 중인 봇 연결이 없으므로 실제 설정 저장은 제공하지 않습니다.

```powershell
python website/server.py --configure
```

Discord 개발자 페이지의 OAuth2 Redirects에는 `http://127.0.0.1:8766/auth/callback`을 등록합니다. Application ID와 Client Secret은 터미널의 안내에 따라 입력하며 Secret은 숨김 입력입니다. Bot Token과 다르며 채팅이나 셸 명령으로 붙여넣지 않습니다.

봇과 함께 실행하려면 봇 실행 환경에 `SHERBET_WEBSITE_ENABLED=1`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`을 설정합니다. 기본은 비활성이고 홈페이지 시작 실패가 공지 봇을 중단하지 않습니다. 홈페이지가 `.env`나 `state.json`을 직접 읽고 쓰지 않습니다.

## 서버 최초 설정과 접속

최초 설정 도구는 `deploy/configure-website.py`입니다. 운영자가 서버 대화형 터미널에서 실행하여 ID와 Secret을 직접 입력하고 마지막 `yes`로 서비스 연결·재시작을 승인합니다. root 전용 설정 파일을 생성하고 기존 설정 파일이 있으면 덮어쓰지 않습니다. 현재 서버에서는 운영자가 이 단계를 완료했습니다.

홈페이지는 `127.0.0.1:8766`에만 바인딩합니다. 승인된 SSH 터널로 로컬 8766을 서버 8766에 연결해 `http://127.0.0.1:8766/#account`에서 접속합니다. 다른 로컬 서버와 포트를 겹쳐 사용하지 않습니다.

로그인 권한 범위는 `identify guilds`입니다. 토큰과 세션은 서버 메모리에만 유지하며 1시간 또는 토큰 만료 후 다시 로그인합니다. 서버 재시작도 로그인 상태를 초기화합니다. 인증 코드가 접근 로그에 남지 않도록 홈페이지 접근 로그는 끕니다.

운영 홈페이지는 `https://sherbetbot.com`으로 연결합니다. 로컬 8766 포트는 Cloudflare Tunnel의 내부 연결용이며 직접 인터넷에 열지 않습니다. 공개 주소를 적용하면 Host 검사 때문에 기존 로컬 URL 대신 도메인으로 접속해야 합니다.

## 공개 도메인 연결 준비

### 웹 랭킹·판매 기간

`#rankings`에서 공개 캐릭터 검색과 Kronos·Scania·Bera·Hyperion 경험치 상위 100명을 조회합니다. `/api/rankings?world=45`와 `/api/rankings?nickname=이름`은 로그인 없이 저장된 게임 정보만 반환합니다. 각 행에 실제 기준일을 표시합니다. 수집 중에는 기준일이 섞일 수 있어 공식 실시간 순위를 보장하지 않습니다.

운영 봇의 RankingStore 경로를 읽기 전용으로 연결합니다. 월드 정렬 인덱스 `idx_characters_web_ranking`은 초기화 시 추가되므로 **운영 적용 전에 수동 DB 백업과 복원 가능 여부를 확인**해야 합니다. SQL 실행 3초 제한·동시 DB 조회 1개·최대 128개 응답의 60초 캐시·IP별 분당 30회 제한을 둡니다. 공개 캐릭터와 최근 기록은 동일한 읽기 트랜잭션으로 조회합니다.

프리렌 판매 기간은 `dist/sales.json` 한 곳을 봇과 홈페이지가 공유합니다. 시작은 공식 점검 완료 공지 기준이며 종료 시각은 exclusive입니다. 홈페이지 날짜는 방문자 시간대와 함께 표시합니다.

2026-09-15 `8132b0a` 공개 준비 변경을 배포했습니다. 운영 홈페이지 로그인 → 에무새의 새장 선택 → test 공지 알림 ON 저장 → Discord `/채널설정` ON 조회 → 홈페이지 OFF 복원까지 실제 검증했습니다. 테스트용 다른 채널 생성이나 메시지 삭제 없이 기존 설정으로 복원했습니다. 앞선 시점의 검증 대기 기록은 이 확인으로 완료됐습니다.

소개 화면의 초대 버튼은 Discord 개발자 페이지의 공식 설치 링크를 사용합니다. 로그인 후 상단에는 사용자 이름과 내 서버 버튼이 표시됩니다. 명령어 결과 예시는 `dist/example-signature.png`, `dist/example-wonderberry.png`에 보관합니다. 다른 명령어는 실제 화면이 준비되면 추가하며 빈 이미지 상자는 표시하지 않습니다.

인증·설정 API는 IP별 분당 120회, 로그인 시작은 별도로 분당 10회까지 허용합니다. 초과하면 HTTP 429와 Retry-After를 반환합니다. IP별 기록은 메모리에만 보관하고 1분 뒤 다음 API 요청에서 정리하며 최대 4,000개 묶음을 유지합니다. 공개 모드에서는 로컬 Tunnel 연결이 전달한 CF-Connecting-IP만 신뢰합니다. 외부에서 원본 포트에 직접 접근할 수 있도록 바꾸지 마세요.

Discord 개발자 페이지의 이용약관·개인정보처리방침 링크는 각각 `https://sherbetbot.com/#terms`, `https://sherbetbot.com/#privacy`로 등록했습니다.

`SHERBET_PUBLIC_ORIGIN=https://실제도메인`을 설정하면 허용 Host·저장 Origin·OAuth 콜백과 Secure 쿠키를 함께 전환합니다. HTTP 공개 주소나 경로·사용자 정보가 포함된 주소는 거부합니다. 미설정 시 기존 로컬 8766 주소를 사용합니다. 변경 후 기존 세션은 재시작으로 종료되며 새 주소에서 다시 로그인합니다.

도메인은 Cloudflare에서 등록한 `sherbetbot.com`입니다. 서버 내부 `127.0.0.1:8766`을 홈페이지 전용 `sherbet-tunnel` 서비스로 연결했습니다. 공개 주소 설정 파일은 `deploy/sherbet-public-origin.conf`이며, 봇 서비스의 별도 `70-public-origin.conf` drop-in으로 설치했습니다.

연결 대상은 `sherbetbot.com` → `http://127.0.0.1:8766`, OAuth 콜백은 `https://sherbetbot.com/auth/callback`입니다. 운영자의 승인으로 Tunnel 서비스 설치·공개 라우트 생성·봇 재시작을 수행했습니다. `www` 주소는 연결하지 않았습니다.

2026-09-15 공식 ARM64 패키지 `cloudflared 2026.9.1` 설치와 서버 인증을 완료했습니다. 인증서와 Tunnel 자격증명은 서버에서만 유지하며 내용은 읽거나 저장소에 복사하지 않습니다. HTTPS 홈페이지·로그인 준비 API 정상 응답과 봇 재연결을 확인했고, Discord 개발자 페이지에도 공개 콜백을 등록했습니다. 운영자가 공개 주소에서 로그인 완료를 확인했습니다. 서버 목록 및 설정 저장의 최종 사용자 검증은 별도입니다. 이후 `5b5121d`의 나머지 변경과 공개 약관·개인정보 안내도 배포했으며, 정책 페이지의 실제 응답과 화면을 확인했습니다.

직접 HTTPS를 구성하는 대안은 `deploy/Caddyfile.example`이며 다음 순서로 적용합니다.

1. 운영자가 소유 도메인을 정하고 서버 공인 IP를 확인합니다. 기존 보조 서버의 IP를 메인 IP로 추측하지 않습니다.
2. 해당 도메인의 DNS A/AAAA를 대상 서버로 연결합니다. 메인 서버의 공인 접근 경로·OCI 네트워크와 OS 방화벽의 80/443 허용 여부를 확인합니다. 8766은 계속 로컬에만 둡니다.
3. Caddy 공식 설치 방법과 현재 OS 패키지를 확인하고 예시의 도메인을 실제 값으로 교체해 설정을 검증합니다. 서비스·네트워크 변경은 승인된 범위에서 수행합니다.
4. 기존 Secret 파일은 읽거나 수정하지 않고 별도 systemd drop-in의 `Environment=SHERBET_PUBLIC_ORIGIN=https://실제도메인`으로 공개 주소만 설정합니다.
5. Discord 개발자 페이지 OAuth2 Redirects에 `https://실제도메인/auth/callback`을 등록합니다.
6. 공개 전 로그인·설정 API의 요청 제한, 개인정보 안내와 실제 초대·지원 링크를 검토합니다. HTTPS 인증서·Host·로그인·권한 거부·설정 저장 검증 후 공개합니다.

참고: [Caddy 자동 HTTPS](https://caddyserver.com/docs/automatic-https), [Discord OAuth2](https://docs.discord.com/developers/topics/oauth2).
