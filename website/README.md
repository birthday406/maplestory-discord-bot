# 샤벳 홈페이지 시안

설정 화면은 가상 프로토타입이며, Discord 로그인·관리자 서버 목록 조회용 로컬 서버를 별도로 제공합니다. 봇 실행·운영 설정에 영향을 주지 않습니다.

프로젝트 루트에서 실행합니다.

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory website/dist
```

브라우저에서 http://127.0.0.1:8765/ 를 엽니다. 별도 패키지 설치나 빌드는 필요 없습니다.

- 소개, 대시보드, 명령어 분류·검색 화면
- 가상 서버와 채널 선택, 알림 켜기·끄기, 역할 선택, 시간 표시 설정
- 브라우저에만 예시 설정 저장, 되돌리기, 미저장 변경사항 이동 확인
- 채널 권한 부족 상태 예시
- 명령어 이미지는 사용자 촬영본을 넣기 위한 자리 표시

`dist/commands.js`는 봇 도움말 목록을 바탕으로 만든 시안용 데이터입니다. 봇 변경에 자동 동기화되지는 않습니다.

## Discord 로그인 준비

프로젝트 루트에서 `python website/server.py`를 실행하고 http://127.0.0.1:8766/#account 를 엽니다. 기존 `aiohttp` 의존성을 사용합니다. 8765의 정적 서버에는 로그인 API가 없습니다.

1. https://discord.com/developers/applications 에서 기존 샤벳 앱을 선택합니다.
2. OAuth2의 Redirects에 `http://127.0.0.1:8766/auth/callback`을 등록하고 저장합니다.
3. 실행 중인 홈페이지 서버를 Ctrl+C로 종료한 뒤 `python website/server.py --configure`로 다시 실행합니다.
4. 본인이 터미널에 Application ID와 OAuth2 Client Secret을 입력합니다. Secret은 숨김 입력이며 파일에 저장하지 않습니다. Bot Token과 다른 값입니다. 채팅으로 전달하지 않습니다.
5. 홈페이지의 Discord 로그인 버튼을 눌러 로그인하고 실제 관리자 서버 목록을 확인합니다.

환경에서 `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`을 제공해도 됩니다. 코드는 `.env`를 읽지 않습니다. 요청 범위는 `identify guilds`이며 이메일·메시지 읽기를 요청하지 않습니다. 토큰과 세션은 서버 메모리에만 유지하고 1시간 또는 토큰 만료 시 다시 로그인합니다. 서버 재시작도 로그인 상태를 초기화합니다. 로그아웃은 이 홈페이지의 세션을 종료하며 Discord 앱 연동 자체를 해제하지는 않습니다.

이 서버는 **127.0.0.1:8766 전용 개발 서버**입니다. HTTP 로컬 쿠키를 사용하므로 그대로 외부에 노출하지 않습니다. 운영 전에는 HTTPS 주소, Secure 쿠키, 공유 세션·요청 제한 등 운영 구성을 별도로 검증해야 합니다. 로그인 응답의 인증 코드가 기록되지 않도록 접근 로그를 끕니다.

실서비스 전에는 봇의 채널·역할 조회와 설정 저장 연결, 실제 초대·지원 링크가 필요합니다. 기존 봇은 `state.json` 전체와 메모리 상태를 함께 관리하므로 홈페이지가 파일을 직접 수정하지 않습니다. 다음 단계에서는 봇 프로세스가 현재 권한을 확인하고 기존 설정 처리를 실행하도록 연결합니다. 실제 로그인은 운영자 입력 후 검증해야 하며 현재는 모의 Discord 응답으로 검증했습니다. 공개 배포와 운영 서버 연결은 하지 않았습니다.

검증: `python -m unittest website.test_server -v`

## 실제 봇 조회 연결 (코드 준비, 운영 미적용)

로그인 후 서버 버튼을 선택하면 해당 서버의 관리자 권한을 다시 확인한 뒤 텍스트·음성 채널, 현재 활성 기능, 서버 오픈 멘션 역할, 봇의 채널별 권한을 조회합니다. 설정 변경 API는 없습니다. 가상 화면의 저장값은 사용하지 않습니다.

`website/bot_view.py`가 봇의 실행 중 메모리 상태를 읽습니다. 운영 파일을 복사하거나 `state.json`을 홈페이지가 직접 읽고 쓰지 않습니다. `/채널설정`에서 바꾼 결과는 다음 조회에 표시됩니다. 모든 조회는 성공 시각과 함께 반환하며 봇 연결·권한·조회 실패를 빈 설정으로 처리하지 않습니다.

메인 봇 실행 환경에 `SHERBET_WEBSITE_ENABLED=1`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`이 설정되어 있을 때만 홈페이지 서버를 함께 실행합니다. 기본은 비활성화이며 홈페이지 시작 실패가 공지 봇 실행을 중단하지 않습니다. 종료 시 홈페이지 서버도 정리합니다. 실제 값은 운영자가 직접 설정해야 합니다.

운영 검증에는 별도 승인된 배포와 환경 설정이 필요합니다. 기존 8766 로컬 서버를 종료하고 SSH 로컬 터널로 `127.0.0.1:8766`을 메인 서버의 `127.0.0.1:8766`에 연결하면 기존 콜백 주소로 검증할 수 있습니다. 홈페이지 포트를 인터넷에 공개하지 않습니다. 다른 서버로 바뀌므로 다시 로그인해야 합니다. 실제 설정의 읽기 검증을 마친 뒤 별도 작업으로 저장 기능을 연결합니다.
