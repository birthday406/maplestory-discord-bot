## 메이플 서버 상태 명령어

`/서버`는 넥슨 공식 서버 상태 API에서 글로벌 메이플의 주요 상시 월드인 `Scania`, `Bera`, `Kronos`, `Hyperion`을 확인합니다. 네 월드 모두 로그인 서버가 정상이고 게임 채널이 하나 이상 열려 있을 때 전체 서버를 정상으로 표시합니다. 계절 서버와 상태 데이터가 없는 테스트 서버는 판정에서 제외합니다.

관리자가 `/서버알림`을 켜면 공식 Discord announcements의 명확한 `Game is up!` 또는 `The game is now up!` 안내에만 기존 서버 오픈 메시지와 설정한 역할 멘션을 보냅니다. 상태 API의 정상 응답, 예정 종료 시각 경과, 캐시샵·채널 점검 완료는 오픈 알림을 발생시키지 않습니다. `/서버` 명령어는 기존처럼 API 상태를 조회합니다.

공지 수정·봇 재시작·같은 점검의 추가 오픈 공지는 SQLite의 점검 ID·원문 메시지 ID·채널별 기록으로 중복 멘션을 방지합니다. 홈페이지 점검 ID가 없으면 UTC 날짜별 한 번으로 제한합니다. 멘션 전 기록을 저장하므로 전송 중 중단되거나 응답이 유실되면 자동 재전송하지 않습니다. 전송 오류는 관리자에게 확인을 요청하며 이 경우 누락 여부를 수동 확인해야 합니다. 인용·취소선·질문·예정 문구는 오픈으로 인정하지 않으며 수집이 멈추면 API로 대체하지 않습니다.


## 시간·환율 채널

`/시간` 또는 `!시간`은 UTC와 미국 서부·중부·동부, 유럽, 한국, 호주의 현재 날짜와 시각을 한 임베드로 보여줍니다. 각 지역의 서머타임과 `PDT`·`PST` 같은 표기는 시간대 데이터에 따라 자동으로 바뀝니다.

관리자가 `/정보채널`에서 종류와 음성 채널을 고르면 채널 이름을 자동으로 갱신합니다. 시간과 네이버 금융의 USD/KRW 매매기준율은 10분마다 갱신합니다. 시간 채널은 Discord의 채널 이름 변경 제한을 피하기 위해 5분보다 짧게 갱신하지 않습니다. 환율 페이지를 읽지 못하면 기존 채널 이름을 유지하고 다음 주기에 다시 시도합니다.

UTC 시각은 별도의 `/utc채널`로 설정하며 `UTC: 19:30` 형식으로 표시합니다.

```text
/정보채널 종류:시간 채널:#시간 동작:ON
/정보채널 종류:환율 채널:#환율 동작:ON
/utc채널 채널:#UTC 동작:ON
```

텍스트 채널에서 환율의 변경 과정도 확인하려면 관리자가 `/환율기록알림`을 사용합니다. 한국시간 날짜별로 메시지 하나만 만들고 10분마다 환율이 실제로 달라졌을 때만 기존 메시지를 수정합니다. 최근 변동은 5개만 표시하며 상승은 `🔴 ▲`, 하락은 `🔵 ▼`로 구분합니다. 기록과 메시지 ID는 `state.json`에 저장되어 봇을 재시작해도 이어집니다.

```text
/환율기록알림 채널:#환율기록 동작:ON
```

봇에는 선택한 음성 채널의 `채널 보기`와 `채널 관리` 권한이 필요합니다. `OFF`는 자동 갱신만 멈추며 현재 채널 이름은 그대로 둡니다.

## 글로벌 리부트 보스 5% 명령어

`/5퍼`만 입력하면 `검밑`의 스우·데미안·루시드·윌·더스크·진 힐라·듄켈 대표 난이도 수치를 한 번에 보여줍니다. 메시지 아래 보스·난이도 드롭다운을 바꾸면 같은 메시지의 총 체력·5% 최소 피해량(K 단위)과 보스 이미지가 갱신됩니다. 보스를 바꾸면 첫 난이도로 시작하며, `검밑`은 난이도 선택이 비활성화됩니다. 실행한 사람만 조작할 수 있고 10분 동안 사용하지 않으면 선택창이 만료됩니다. 기존 보스·난이도 직접 입력 옵션은 제거했습니다.

## 알림 채널 설정 명령어

`/알림설정확인`은 현재 서버의 알림 채널, 서버 오픈 알림의 멘션 역할, 시간·UTC·환율 정보 채널을 관리자에게만 보여줍니다. 결과는 실행한 사람에게만 보이며 역할 알림은 울리지 않습니다. 등록된 채널이 없으면 해당 종류에 `등록된 채널 없음`을 표시합니다. 큐브세일은 채널 예약 상태만 표시합니다.

봇이 현재 서버에서 확인할 수 있는 채널만 표시하므로 삭제되었거나 확인할 수 없는 채널은 목록에서 제외됩니다. `ON`은 저장된 설정이며 실제 전송 권한이나 API 정상 여부를 검사한 결과는 아닙니다. 조회는 설정을 변경하지 않습니다.

아래 명령어는 서버 관리자만 실행할 수 있습니다. `채널`에서는 현재 서버의 텍스트 채널을 선택하고, `동작`에서는 `ON` 또는 `OFF`를 선택합니다. 같은 알리미에 여러 채널을 등록할 수 있습니다.

```text
/공지알림 채널:#공지 동작:ON
/썬데이알림 채널:#메인채팅 동작:ON
/썬데이목록알림 채널:#썬데이메이플 동작:ON
/미라클큐브알림 채널:#메인채팅 동작:ON
/캐시이동알림 채널:#메인채팅 동작:ON
/우르스알림 채널:#메인채팅 동작:ON
/서버알림 채널:#메인채팅 동작:ON 역할:@메이플알림
/서버알림 채널:#메인채팅 동작:OFF
/큐브세일알림 채널:#메인채팅 동작:ON
```

- `/공지알림`: `maintenance`, `sale`, `general`, `update`, `events` 번역 공지
- `/썬데이알림`: 해당 주 Sunny Sunday가 시작될 때 보내고 24시간 뒤 삭제하는 당일 알림
- `/썬데이목록알림`: 새 패치노트에서 전체 Sunny Sunday 목록을 발견했을 때 보내는 알림
- `/미라클큐브알림`: 미라클 타임 당일 알림과 종료 1시간 전 알림
- `/캐시이동알림`: 캐시이동 시작 당일 알림과 종료 24시간 전 알림
- `/우르스알림`: 미국 서부의 서머타임을 자동 적용해 골든타임 시작·종료 시각에 보내는 알림
- `/서버알림`: 공식 Discord의 명확한 Game is up 안내에만 설정한 역할을 멘션하는 서버 오픈 알림
- `/큐브세일알림`: 향후 큐브세일 자동 알림을 받을 채널을 미리 저장하는 설정

이미 `ON`인 채널을 다시 켜도 중복 전송하지 않습니다. 목록 알림을 새 채널에 처음 켜면 `state.json`에 저장된 최신 전체 목록을 그 채널에 한 번 보내며, 이후에는 다음 패치노트의 새로운 목록이 나올 때까지 다시 보내지 않습니다.

서버 오픈 알림은 채널마다 서로 다른 역할을 설정할 수 있습니다. 역할이 멘션 가능 상태가 아니면 봇에 `모두 멘션하기` 권한이 있어야 실제 알림이 울립니다.

## HEXA 강화 계산 명령어

Discord에서 `/헥사`를 입력하고 코어 종류, 현재 레벨, 목표 레벨을 선택하면 필요한 솔 에르다와 솔 에르다 조각 합계를 계산합니다.

`/헥사`·`/성장의비약`·`/에픽던전`·`/심볼계산기`는 명령어 뒤에 옵션을 붙이지 않습니다. 명령어만 실행한 뒤 종류·적용 여부는 드롭다운에서 선택하고, **수치 입력** 버튼으로 레벨·경험치 등을 입력한 다음 **계산하기**를 누릅니다. 본인에게만 보이는 같은 메시지에서 값을 바꿔 다시 계산할 수 있으며, 10분간 사용하지 않으면 설정창이 만료됩니다. 심볼의 보약·엘라노스는 마지막 저장값이 기본 선택됩니다.

```text
/헥사
```

지원하는 코어 종류는 `스킬 코어`, `3rd 스킬 코어`, `마스터리 코어`, `강화 코어`, `공용 코어`, `직업군 공용 코어`입니다.
현재 레벨은 0~29, 목표 레벨은 1~30 범위에서 선택할 수 있습니다.

## 채널 추천 명령어

Discord에서 `/채널추천`을 입력하면 메이플스토리 게임 채널 1~40 중 하나를 무작위로 추천합니다. 명령어를 실행한 사용자의 Discord 닉네임과 추천 채널을 20가지 안내 문구 중 하나로 무작위로 보여주며, 닉네임 끝 글자의 받침에 따라 `아`와 `야`를 자연스럽게 구분합니다.

## PSSB 시뮬레이터

Discord에서 `/스스비`를 입력하고 `1회` 또는 `5회`를 선택하면 현재 공식 Premium Surprise Style Box 확률표로 결과를 추첨합니다. 명령어 실행과 `다시 뽑기` 버튼 클릭 때마다 공식 표를 새로 읽으므로 구성품 변경을 코드에 직접 입력할 필요가 없습니다.

이 명령어는 Discord 언어가 한국어일 때 `/스스비`로 표시되며 `/ssb`로 검색할 수 있습니다. 초성 별칭 `/ㅅㅅㅂ`도 같은 기능을 실행합니다.

성별 아이템 두 개가 확률 하나를 공유하면 한 보상으로 합쳐 표시하며, 각 추첨은 독립적이므로 같은 아이템이 중복으로 나올 수 있습니다. 1회와 5회 모두 메시지 한 개로 전송하며, 5회 결과는 실제 GMS SSB처럼 아이콘 다섯 개가 가로로 놓인 이미지 한 장으로 표시합니다. 확률이 2.00% 이하인 아이템은 보라색 슬롯과 `✨` 표식, 2.00%를 초과하는 아이템은 회색 슬롯을 사용합니다. 임베드 아래에는 처음 실행부터 `다시 뽑기`까지 사용한 누적 상자 수를 표시합니다.

`기대값 계산하기` 버튼을 누르면 현재 결과 아이템의 공식 등장 확률, 평균적으로 필요한 상자 수, 평균 구매 비용과 내 누적 상자 수 안에 한 번 이상 얻을 확률을 보여줍니다. 구매 비용은 낱개 3,600 NX와 11개 세트 36,000 NX 중 가장 저렴한 조합으로 계산합니다. 같은 아이템이 중복된 결과에서는 한 번만 계산합니다. `다시 뽑기`와 기대값 버튼은 처음 명령어를 실행한 사용자만 누를 수 있습니다.

배경 광원과 슬롯은 GMS 클라이언트 리소스를 사용하고, 아이템 아이콘은 로컬 WZ 데이터베이스에서 영문명이 정확히 연결되는 일반 장비에 표시합니다. 데이터베이스에 없거나 독립 아이콘이 없는 아이템도 빈 슬롯과 결과 이름은 남습니다.

## 퍼밀리어 잠재능력 시뮬레이터

Discord에서 `/퍼밀리어`를 입력하면 유니크 등급 퍼밀리어 카드의 잠재능력 두 줄을 무작위로 추첨합니다. 첫 번째 줄은 항상 유니크이며, 두 번째 줄은 99% 확률로 에픽, 1% 확률로 유니크가 나옵니다. 두 번째 줄도 유니크가 나오면 `더블 프라임`으로 표시합니다.

옵션과 가중치는 사용자가 제공한 커뮤니티 표본 확률표를 사용합니다. 표본에서 한 번도 나오지 않은 `보스 몬스터 공격 시 데미지 +35%`는 추첨에서 제외했습니다. 같은 옵션이 두 줄에 중복으로 나올 수 있습니다.

결과는 GMS 클라이언트에서 추출한 실제 퍼밀리어 상세 카드 UI에 잠재능력 두 줄을 넣은 이미지 한 장으로 표시합니다. 시뮬레이터의 고정 기본 외형은 캐시 펫 `Sherbet`이며, 등급은 유니크·레벨은 1로 표시합니다. 한글 렌더링에는 SIL Open Font License 1.1의 나눔고딕을 사용합니다.

결과의 `다시 뽑기` 버튼을 누르면 같은 메시지의 잠재능력과 카드 이미지를 다시 추첨하며, 이미지와 함께 누적 횟수를 표시합니다. 봇은 시작할 때 가능한 4,784개 조합의 확률·평균 기대 횟수와 현재 조합만큼 희귀하거나 더 희귀한 결과가 실제로 나올 확률을 `familiar.db`에 미리 저장합니다. `기대값 계산하기` 버튼은 현재 조합 한 건을 DB에서 읽고 내 누적 횟수 안에 이 결과를 얻을 확률도 함께 보여주며 누구나 사용할 수 있습니다. `다시 뽑기`는 처음 명령어를 실행한 사용자만 누를 수 있고 두 버튼 모두 24시간 동안 유효합니다.

## 연마석 시뮬레이터

같은 메시지에서 준비 화면·GIF·정적 결과를 표시하는 초기 방식입니다. GIF 시작의 준비 화면 0.5초만 추가로 유지하며 이 시간도 조작 잠금에 포함합니다. 새 메시지를 생성하거나 기존 메시지를 삭제하지 않습니다. 실제 재재생 완화 여부는 사용자 환경에서 확인합니다.

`/연마석`을 실행하면 GMS 통합 강화창의 반지 연마 탭을 사용한 준비 이미지가 표시됩니다. Lv.4에서는 생명의 연마석 1~10개(개당 10%, 10개 확정), Lv.5에서는 신념의 연마석 1~20개(개당 5%, 20개 확정)를 드롭다운으로 선택합니다. `강화` 버튼을 눌러야 추첨하며 명령 실행만으로는 추첨하지 않습니다. 신념에서 생명으로 변경할 때 선택 개수가 10개를 넘으면 10개로 맞춥니다. 6개 이상은 기존 5개용 시각 효과를 재사용하되 사용량·성공 확률은 실제 선택값을 표시합니다.

```text
/연마석
```

강화는 선택한 레벨에서 매번 독립 추첨합니다. 성공해도 선택 레벨을 자동으로 올리지 않습니다. 조건 변경 시 결과 표시만 초기화하고 시도·성공·실패·실제 사용 연마석 누계는 유지합니다. 실행자만 조작할 수 있고 10분 미사용 시 버튼을 비활성화하고 만료 문구를 표시합니다. 다시 사용하려면 `/연마석`을 새로 실행해야 합니다. 게임 아이템·메소는 소비되지 않습니다. `/시드링` 명령과 직접 입력 옵션은 제거했습니다.

화면은 원본 패널·반지·연마석 아이콘을 사용한 418×342 이미지와 조작 버튼을 한 메시지에 표시합니다. 준비 0.5초와 GIF 이펙트가 끝날 때까지 버튼을 비활성화하고 중복 강화·조건 변경을 막습니다. 종료 시 같은 메시지에 정적 결과 이미지·결과 문구·누계를 표시하고 버튼을 활성화합니다. GIF 마지막 결과 화면 2초는 조작 대기에 포함하지 않습니다. GIF 실패 시 재추첨 없이 같은 결과의 정적 이미지로 대체합니다. 글꼴은 Noto Sans KR을 사용합니다. 실제 Discord 재재생 여부는 사용자 환경에서 추가 확인합니다. `tools/export_polisher_ui.ps1`과 `tools/export_polisher_effects.ps1`로 GMS WZ에서 자료를 추출할 수 있으나 봇 실행에는 WZ가 필요하지 않습니다.

핫위크는 보상 표 또는 날짜별 목록에서 UTC 자정~다음 자정 수령 일정을 읽습니다. 큐브세일은 Glowing·Bright 등 일반 큐브의 할인 및 할인 패키지 기간을 읽고, Violet·Unicube·Equality·Bonus Bright 같은 특수 큐브의 단순 기간 한정 판매는 제외합니다. 날짜는 사용자 현지 시간으로 표시하며 보상·판매 상세는 원문 영어를 유지하고 공식 링크와 썸네일을 제공합니다. 진행 중·예정 일정 중 최대 10건을 표시하고 종료된 일정은 제외합니다.

## EXP 교환권 계산기

`/exp쿠폰`은 명령어 입력 옵션 없이 실행하며, 실행하면 본인에게만 보이는 설정창이 열립니다. **쿠폰 종류**와 **버닝**은 드롭다운으로 고르고, **수치 입력** 버튼에서 시작레벨·경험치 퍼센트·쿠폰 개수를 입력한 다음 **계산하기**를 누르세요. 입력한 레벨에 맞는 쿠폰만 표시하며 숫자를 바꾼 뒤 같은 창에서 다시 계산할 수 있습니다. 개수는 `3,000`처럼 쉼표를 넣어도 됩니다. 10분 동안 사용하지 않으면 설정창이 만료되므로 명령어를 다시 실행하세요. 버닝 선택은 기존처럼 기억하지만 레벨·경험치·개수는 랭킹과 자동 연동하지 않습니다.

제공받은 최신 표를 기준으로 일반 EXP 교환권은 Lv.200~260, 상급 EXP 교환권은 Lv.260~299에서 계산합니다. 버닝은 `X`, `하이퍼버닝`, `비욘드버닝` 중 하나를 선택하며 각각 Lv.260과 Lv.270에서 정확히 끝납니다. 설정창을 열면 사용자별로 마지막에 선택한 버닝 값을 다시 사용하고, 저장된 값이 없는 첫 사용자는 `X`를 기본으로 적용합니다. 선택값은 봇이 재시작되어도 유지되도록 Discord 사용자 ID와 함께 `state.json`에 저장합니다. 결과 제목에는 일반 교환권은 EV, 상급 교환권은 AEV 커스텀 이모지를 표시합니다. 사용 가능한 마지막 레벨을 넘거나 Lv.300에 도달하면 남은 교환권은 적용하지 않습니다.

## 아케인·어센틱 심볼 계산기

`/심볼계산기`에서 지역, 현재 레벨·성장치, 목표 레벨, 보약 레벨과 엘라노스 적용 여부를 선택하면 추가로 필요한 심볼 개수와 강화 메소, 일일 퀘스트 기준 예상 완료일을 계산합니다. 심볼 종류는 선택한 지역으로 자동 판별합니다. 보약 레벨과 엘라노스를 생략하면 사용자별 마지막 선택값을 사용하며, 저장값이 없는 첫 사용은 보약 없음·엘라노스 미적용을 기본으로 적용합니다. 선택값은 Discord 사용자 ID와 함께 `state.json`에 저장되어 봇 재시작 후에도 유지됩니다.

```text
/심볼계산기
```

- 아케인 심볼: 일일 기본 20개, 최대 Lv.20
- 어센틱·그랜드 어센틱 심볼: 일일 기본 10개, 최대 Lv.11
- 보약: 없음 또는 1~6레벨
- 엘라노스 적용: `(기본 심볼 + 보약 보너스) × 120%`의 소수점을 버립니다.
- 엘라노스 미적용: `기본 심볼 + 보약 보너스`를 지급량으로 사용합니다.
- 아케인 심볼: 일일퀘만 수행한 경우와 지역별 주간퀘 120개를 이번 주에 수행한 경우·수행하지 않은 경우를 함께 표시합니다.

선택한 조건은 2026년 9월 8일 23:59 UTC까지만 계산하며, 이후에는 보약과 20% 추가 지급을 제외한 기본 심볼 개수만 적용합니다. 예상 완료일은 명령어를 실행한 날의 일일 퀘스트와 이번 주 주간 퀘스트를 아직 받지 않은 성장치로 계산합니다. 주간퀘 120개에는 엘라노스와 보약 보너스를 적용하지 않습니다.

## GMS 캐릭터 랭킹

`/랭킹 닉네임`은 넥슨 공식 북미 GMS 랭킹에서 캐릭터를 찾아 캐릭터 이미지, 레벨·경험치 진행률, 직업·월드, 전체·월드·유니온·업적 순위, 메이플 종합 지수와 태그를 임베드 없이 한 장의 이미지로 보여줍니다. 자동 수집하거나 새로 공식 조회한 캐릭터의 날짜별 경험치를 `ranking.db`에 최근 90개 기준일 동안 유지하고 이전 기록은 아래 월별 압축 보관 정책을 따릅니다. 최근 7일·14일·30일의 일평균 경험치와 최근 14일치 경험치 변화를 표시합니다. 해당 기간의 기록이 모두 있어야 일평균을 계산하며 부족한 값은 `-`로 표시합니다. 최근 7일 평균을 기준으로 다음 레벨까지 남은 경험치와 예상 소요일도 함께 보여줍니다.

경험치 그래프는 청회색 바탕, 하늘색 선과 라임색 포인트를 사용합니다. 그래프 왼쪽 눈금은 최고값에 맞춰 자동 조절하고 값이 위쪽 배지와 겹치지 않도록 여유를 둡니다. 기록 사이에 레벨이 올랐다면 해당 날짜의 경험치 값 위에 `Lv.296 달성` 같은 주황색 배지를 표시합니다. Lv.300 캐릭터는 경험치 진행률 대신 최고 레벨 달성 안내를 표시합니다.

```text
/랭킹 닉네임:Home
```

한 번 닉네임을 입력해 조회하면 그 Discord 계정의 기본 캐릭터로 기억합니다. 이후에는 `/랭킹`만 입력해도 마지막으로 등록한 캐릭터를 다시 조회합니다. 다른 캐릭터를 조회하면 기본값도 그 이름으로 바뀝니다.

닉네임은 메이플스토리 규칙에 맞춰 최대 12바이트까지 받습니다. 한글은 글자당 2바이트, 영문과 숫자는 글자당 1바이트로 계산합니다.

유니온과 업적은 계정의 대표 캐릭터만 공식 랭킹에 표시됩니다. `/랭킹`은 전체 수집기가 이미 저장한 대표 캐릭터 데이터와 캐시된 프로필을 합쳐 즉시 사용하며, 명령어 실행 중에는 대표 여부를 확인하는 추가 요청을 보내지 않습니다. 저장된 유니온·업적이 모두 없는 캐릭터는 `부캐` 태그와 `대표 캐릭터에서만 확인 가능` 안내를 표시하고, 우선 수집기가 백그라운드에서 다음 갱신을 처리합니다.

**메이플 종합 지수**는 0.00~99.90점의 재미용 종합 점수입니다. 캐릭터 성장(레벨·경험치·전체 순위) 40점, 유니온(레벨·순위) 30점, 업적(점수·순위) 30점을 합산합니다. 세 랭킹이 모두 1위면 99.90점으로 고정합니다. 이미지에는 점수 단계와 강점 분야를 조합한 태그를 항상 3개 표시합니다. 각 태그는 종합 지수가 아니라 해당 태그 자체의 기준 점수에 따라 레전더리·유니크·에픽·레어·커먼 단계의 초록·금색·보라·파랑·회색 캡슐 배경을 사용합니다.

`/닉네임추적 닉네임`은 연속된 완전 수집일의 월드·직업·레벨·경험치·순위를 비교해 저장된 닉네임 변경 후보를 보여줍니다. 유니온·업적 값이 있으면 추가 검증 신호로 사용하며, 공식 계정 식별자가 없으므로 결과는 확정이 아닌 추정입니다. 변경이 연결된 캐릭터는 `/랭킹` 이미지의 현재 닉네임 옆에 변경 전 닉네임도 표시합니다. 연결 가능한 변경 기록이 없는 신규 관측 캐릭터는 첫 관측일과 함께 Lv.260 이상 신규 진입·월드 리프·랭킹 재등장 가능성을 안내하며 닉네임 변경으로 저장하지 않습니다.

공식 GMS 랭킹 화면의 공개 응답을 사용하므로 넥슨 사이트 구조가 바뀌거나 갱신 중이면 잠시 결과가 나오지 않을 수 있습니다.
외부 랭킹 사이트의 과거 기록을 가져오지 않으므로 기존 수집 기록이 없는 첫 공식 조회에는 기록 시작 안내만 표시됩니다. `/랭킹`은 현재 기준일(17:10 UTC 전환)의 경험치 기록이 있으면 공식 랭킹 요청 없이 저장값을 표시합니다. 프로필 캐시가 없어도 수집된 스냅샷으로 카드를 만듭니다. 현재 기준일 기록이 없으면 `오늘 기록이 없어 최신 정보를 조회하고 있습니다`라고 안내하고 최대 45초 동안 공식 최신 조회를 기다립니다. 같은 캐릭터의 동시 요청은 하나로 합치고, 대기 중 수집기가 채운 당일·이후 기록은 덮어쓰지 않습니다. 공식 사이트 자체가 아직 갱신되지 않았다면 새 조회값도 전날과 같을 수 있습니다.

최신 조회에 실패하거나 캐릭터가 일시적으로 검색되지 않으면 기존 기록과 실패 안내를 보여줍니다. 기존 기록도 없으면 조회 실패 또는 검색 결과 없음으로 안내합니다. 캐시를 읽을 때는 날짜별 기록을 쓰지 않으며, 정상적인 새 공식 조회·수집값만 저장합니다. 카드의 레벨·경험치·전체 순위는 최신 스냅샷을 사용하고 `기록 업데이트`는 그 기록의 실제 기준일을 표시합니다. 날짜별 기록이 없는 기존 프로필은 `기준일 확인 불가`로 표시합니다. 캐시와 수집값이 달라진 경우 캐시의 월드 순위는 표시하지 않으며, 유니온·업적 등 보조 정보는 별도로 저장된 프로필·대표 수집값을 사용합니다.

북미 주요 4개 월드(Scania·Bera·Kronos·Hyperion)의 기록은 네 수집기가 각각 1초마다 1페이지, 최대 10명씩 자동 수집합니다. 각 수집기는 맡은 샤드의 높은 순위부터 내려가며, 서버가 재시작되어도 DB 체크포인트에서 이어집니다. 공식 API가 403을 보내면 5분·15분·1시간·최대 6시간, 429를 보내면 1분부터 최대 1시간까지 단계적으로 요청을 건너뛴 뒤 같은 순위부터 다시 시도합니다. 정상 응답이 한 번 나오면 대기 단계가 초기화되며, 각 월드에서 Lv.260 미만을 만나면 그 월드의 당일 경험치 수집을 마칩니다. `/랭킹`으로 직접 조회한 캐릭터는 메인 봇의 우선 갱신 대기열에 들어가 다음 기준일에 먼저 갱신됩니다.

### 수집기 4샤드 분산 실행

현재 운영 수집은 메인 1대와 보조 3대가 같은 주요 4개 월드(Scania·Bera·Kronos·Hyperion)를 네 샤드로 나눠 처리합니다. 각 서버는 `RANKING_WORKER_SHARD_COUNT=4`와 서로 다른 `RANKING_WORKER_SHARD_INDEX=0`~`3`을 사용하며, `RANKING_WORKER_NAME`도 서로 겹치지 않게 설정합니다. 한 서버가 한 월드를 전담하는 방식이 아니라 각 월드의 페이지를 네 수집기가 교차해서 담당하므로 인원이 많은 Kronos도 네 서버가 함께 처리합니다.

각 수집기는 자신의 공인 IP에서 1초당 1페이지의 요청 시작 제한을 지킵니다. 느린 API 응답 때문에 요청 간격이 늘어나지 않도록 응답은 기본 3개까지 겹쳐 기다리며 `RANKING_WORKER_CONCURRENCY`로 조절할 수 있습니다. 월드별 Lv.260 이상 경험치 랭킹을 모두 수집한 뒤 같은 수집기가 Lv.260 이상 대표 캐릭터의 유니온·업적 랭킹을 이어서 순환 수집합니다.

운영 `ranking.db`는 메인 Discord 봇만 쓰며 봇 자체의 전체 랭킹 순회는 `RANKING_COLLECTION_IMPORT_ONLY=1`로 끕니다. 메인 수집기는 완성한 JSONL을 메인 서버의 `ranking-inbox`에 바로 두고, 보조 수집기는 60페이지를 원자적인 JSONL 묶음으로 만든 뒤 SSH로 같은 폴더에 전송합니다. 메인 봇은 전송이 끝난 파일만 백그라운드에서 합치고 `processed`로 옮깁니다. 늦게 도착한 과거 묶음은 날짜별 기록만 채우며 더 최신인 캐릭터 현재값을 되돌리지 않습니다.

MapleBot 과거 경험치 백필은 보조 서버에서 체크포인트와 현재 레벨을 남기며 실행합니다. 그래프와 무관한 이미지·폰트·미디어는 받지 않으며, 정상 프로필에 경험치 그래프가 없는 캐릭터도 체크포인트에 기록해 재시작 때 다시 조회하지 않습니다. 오류로 종료되면 5초 후 같은 레벨부터 자동 재실행합니다. 봇 소유자는 봇과의 Discord DM에서 `백필 상태` 또는 `백필 확인`으로 진행량을 확인하고 `백필 재시작`으로 수동 재시작할 수 있으며 띄어쓰기는 생략해도 됩니다. 메인 서버에는 `BACKFILL_CONTROL_HOST`, `BACKFILL_CONTROL_SSH_KEY`를 설정하며 해당 키는 보조 백필 서버에만 접속할 수 있는 전용 키를 사용합니다.

모든 수집기에는 `RANKING_WORKER_WORLD_IDS=45,19,1,70`을 사용합니다. 보조 서버의 `RANKING_SYNC_TARGET`에는 메인 서버의 `ranking-inbox` SSH 경로를, `RANKING_SYNC_SSH_KEY`에는 전송 전용 키 경로를 설정합니다. 메인 서버의 `processed`와 보조 서버의 `sent` 묶음은 복구 확인 전까지 자동 삭제하지 않습니다. 저장소의 `deploy/systemd`에는 메인 봇의 import-only 설정, 수집기 서비스, 샤드별 예시 설정이 있습니다.

### 일일 수집 검사

페이지 응답에 같은 캐릭터가 반복되면 이름 기준 한 명으로 집계합니다. 원본과 중복 횟수 로그는 보존하고 중복만으로는 경고 DM을 보내지 않습니다. 업적 응답에 섞인 다른 월드 캐릭터는 같은 날짜 스냅샷의 실제 소속 월드로 구분하며, 월드 미확인 이름은 전체에서 한 번만 검사합니다. 같은 날짜·종류의 정상 대표 값이 대기 테이블에 있으면 `값 보관됨·당일 경험치 기록 대기`로 안내하고, 스냅샷과 정상 대기 값에 모두 없는 경우는 실제 저장 누락으로 경고합니다. 완료 표식·페이지 누락·인원 감소 검사는 유지합니다. 이번 중복·대기 구분은 2026-09-10 운영에 적용했습니다. 이미 저장된 보고서와 DM은 변경하거나 재전송하지 않습니다.

수정 코드에서는 유니온·업적의 진행 위치에도 UTC 기준일을 저장합니다. 같은 기준일의 재시작은 이어서 수집하고, 새 기준일에는 각 샤드의 첫 페이지부터 시작합니다. 요청 중 기준일이 바뀐 대표 랭킹 응답은 저장하지 않고 새 기준일에 다시 요청합니다. 기존 날짜 없는 진행 위치는 업그레이드 후 첫 사용 시 한 번 초기화합니다. 요청 속도 제한은 그대로 유지합니다.

유니온·업적이 경험치보다 먼저 도착하면 `ranking_pending_representatives`에 원래 날짜와 값을 보관합니다. 같은 날짜의 실제 경험치 기록이 생기면 한 트랜잭션에서 합치고 반영된 대기 항목만 해제합니다. 아직 경험치가 없는 항목은 재시작 후에도 보존하며, 빈 경험치 스냅샷을 만들거나 다른 날짜의 기록에 끼워 넣지 않습니다. 운영 DB 백업에 대기 항목도 함께 포함됩니다.

2026-09-09 사용자 승인 후 메인 봇과 수집기 4대에 수정본을 적용하고 재시작했습니다. 운영 DB 전체 백업과 무결성 검사 후 보존 배치를 근거로 2026-09-08 Kronos 26명의 유니온 값·순위만 복구했습니다. 기존 검사 보고서는 당시 상태로 보존하므로 이미 받은 경고 메시지가 자동 수정되지는 않습니다. 페이지 빈 구간은 정상 수집이 다시 채우며 전날 자료를 당일 기록으로 복사하지 않습니다.

메인 봇은 import-only 모드에서 5분마다 검사 준비 상태를 확인합니다. 4개 월드 × 4개 샤드의 완료 표식이 모인 경험치·유니온·업적 단계부터 하루 한 번 검사합니다. 누락 페이지, 실제 DB 저장 누락, 대표 값의 당일 경험치 기록 대기, 직전 정상 검사 대비 월드별 인원 10% 이상 감소를 봇 소유자 DM으로 알립니다. 다음 기준일의 17:10 UTC까지 완료되지 않은 단계도 보고합니다. 같은 이름은 집계에서 한 명으로 합치며 중복만으로 DM을 보내지 않고 원본과 로그를 보존합니다.

유니온·업적은 실제 수집된 Lv.260 이상 대표 캐릭터만 비교하므로 부캐에 해당 값이 없다는 이유만으로 경고하지 않습니다. 업적의 전역 응답에 섞인 다른 월드 캐릭터는 같은 기준일 스냅샷의 실제 월드로 구분하고, 미등록 캐릭터와 업적 값 누락은 계속 검사합니다. 정상 결과는 `ranking_audit` 로그에 남기고, 검사 결과·전송 성공 여부는 `ranking_audit_reports`에 보존해 재시작 후 같은 경고를 반복하지 않습니다. DM 전송 실패는 다음 검사에서 재시도합니다.

수집 배치 형식이 바뀌는 배포에서는 메인 봇과 수집기 4대의 관련 코드를 함께 갱신해야 합니다. 검사 판단만 바뀌면 메인에서 적용하며, 공유 검사 모듈은 보조에도 동기화합니다. 이 검사는 검사 근거를 포함한 첫 배치부터 적용됩니다. 중간에 배포한 첫날은 이전 페이지의 검사 근거가 없어 누락 경고가 발생할 수 있으며, 다음 기준일부터 전체 수집 검사가 가능합니다. 최초 배치 수신 이후에는 배치가 전혀 도착하지 않은 날도 다음 기준일에 경고합니다. 검사 근거와 기존 스냅샷은 자동 삭제하지 않습니다.

봇 소유자는 봇과의 Discord DM에서 `랭킹 상태` 또는 `랭킹 확인`을 보내 현재 기준일·UTC 시작 시각·저장 인원·진행률·예상 종료 시각과 수집기별 위치를 확인할 수 있습니다. 네 수집기가 모두 경험치 수집을 끝내고 유니온·업적 단계로 넘어가야 100% 완료로 판정합니다. 진행 중 목표 인원은 당일 모집단이 있으면 그 값을, 없으면 직전 저장일의 Lv.260 이상 인원을 사용하며 이 기준을 넘더라도 완료 전에는 최대 99.9%로 표시합니다. 완료 후에는 실제 완료 시각과 총 소요 시간을 표시하고 최근 10분 및 당일 누적 실패 배치 수도 함께 보여줍니다.

`/랭킹`으로 조회에 성공한 캐릭터는 중복 없이 우선 대상에 등록됩니다. 다음 날짜의 자동 수집에서는 이 캐릭터들을 최근 조회 순서로 하루 한 번 먼저 갱신한 뒤 월드별 상위 랭킹 수집을 이어갑니다. 명령어 조회와 자동 수집을 포함한 모든 공식 랭킹 요청은 같은 요청 간격 제한을 공유합니다.

각 수집기는 페이지마다 자신의 체크포인트를 저장하고, 60페이지 단위 JSONL이 메인 서버에 도착하면 메인 봇이 `ranking.db`에 반영합니다. 별도 백업은 일일 랭킹 수집을 마친 뒤 프로젝트 밖 `~/maplestory-discord-bot-backups/ranking.db`에 만들고 SQLite 무결성 검사를 실행합니다. 자동 수집을 켜지 않아도 `/랭킹`으로 직접 조회한 기록은 같은 DB에 저장됩니다.

공식 랭킹의 실제 일일 갱신 시각을 측정할 때는 `python tools/probe_ranking_update.py`를 실행합니다. 최근 경험치 변경 캐릭터 5명을 10분마다 확인하고 최초 변경 감지 시각을 한국시간으로 `ranking-update-probe.json`에 남긴 뒤 종료합니다. 기본 감시 시간은 24시간입니다.

### 랭킹 기록 90일 보관과 월별 압축 아카이브

운영 DB에는 현재 랭킹 기준일을 포함한 최근 90개 기준일을 유지합니다. 예를 들어 기준일이 2026-09-07이면 2026-06-10 이후를 DB에 남기고 그 이전을 보관 대상으로 삼습니다. 이전의 무조건 30일 삭제는 하지 않습니다.

메인 봇은 기준일마다 한 번 백그라운드에서 오래된 기록을 최대 10,000행씩 월별 폴더의 `JSONL.gz` 묶음으로 보관합니다. 늦게 도착한 과거 기록이나 정정 기록은 기존 압축본을 덮어쓰지 않고 새 묶음으로 추가합니다. 현재 캐릭터 정보·닉네임 변경 기록과 최초 관측일은 운영 DB에 남습니다. 오래된 상세 성장 기록은 아래 복원 도구로 별도 조회할 수 있습니다.

보관본을 gzip으로 다시 읽어 SHA-256·행 수·스키마를 확인하고 메모리 SQLite에 실제 복원해 값까지 비교합니다. 별도 저장소에 복사한 파일도 같은 검증을 통과해야 해당 데이터만 DB에서 정리합니다. 압축 중 수정된 DB 행은 지우지 않고 다음 묶음으로 보관합니다. 압축·복사·검증 실패 시 해당 묶음의 원본은 남기며 실패 단계는 UTC 시각과 함께 로그에 남습니다. 다음 기준일 또는 재시작 후 다시 시도할 수 있습니다.

설정 항목:

| 환경변수 | 용도 |
|---|---|
| `RANKING_ARCHIVE_PATH` | 기본 보관 폴더. 생략하면 기존 DB 백업 폴더 아래 `snapshots` 사용 |
| `RANKING_ARCHIVE_REPLICA_PATH` | 미리 마운트된 별도 저장소의 복사 폴더. 미설정이면 보관·DB 정리를 건너뛰고 원본 유지 |

복사 폴더는 사전에 준비되어 있어야 하며 DB 및 기본 보관 폴더와 다른 파일시스템이어야 합니다. 같은 디스크의 다른 폴더를 복사본으로 지정하면 정리를 거부합니다. 서로 다른 파일시스템이라는 검사는 최소한의 확인이므로 실제로 독립된 디스크·백업 서버 등인지 관리자가 확인해야 합니다. 네트워크 저장소라면 파일 동기화(`fsync`)를 지원해야 합니다. 이 기능은 저장소 생성·마운트·외부 서비스 가입을 자동으로 하지 않습니다.

이미 보관된 파일과 미완성 `.partial-*` 파일은 자동 삭제하지 않습니다. 아카이브 전체 용량도 계속 증가하므로 두 보관 위치의 여유 공간을 관리해야 합니다. SQLite는 삭제된 공간을 재사용하므로 운영 DB 파일이 즉시 작아지지는 않으며 자동 `VACUUM`도 실행하지 않습니다.

압축본만으로 **새 조회용 DB**를 복원하는 예시입니다. 이 명령은 기존 DB를 덮어쓰지 않으며 기본 보관소 또는 복사 보관소 중 한 곳만 지정합니다.

```powershell
python -m ranking_archive "D:\RankingArchives" "D:\ranking-archive-restored.db"
```

월 하나만 복원하려면 보관 폴더 대신 그 안의 `2026-05` 같은 월 폴더를 지정합니다. 복원된 DB에는 `ranking_snapshots` 테이블만 들어 있으며 실행 중인 봇의 DB를 대신하는 파일이 아닙니다. 같은 캐릭터·날짜의 여러 보관본은 보관 시각순으로 적용해 마지막 정정값을 사용합니다. 복원이 실패한 출력 파일은 다시 사용하지 말고 새 출력 경로로 재시도합니다. 배포 시 `ranking_archive.py`, `ranking_store.py`, `maple_bot.py`를 함께 반영해야 합니다.

## 명령어 도움말

`/명령어`는 일반 사용자가 쓸 수 있는 계산기, 시뮬레이터와 일정 확인 명령어를 한 화면에 보여줍니다. 안내는 명령어를 실행한 사용자에게만 표시됩니다.

`/ㅁ`, `/심볼`, `!심볼`은 `Sacred Symbol/claim`, `Arcane Symbol/claim`, `Sol Erda Fragment`, `/partyleave`를 각각 별도의 코드 블록으로 보여줍니다. PC에서는 각 코드 블록의 복사 버튼을 누르고, 모바일에서는 코드 블록을 길게 눌러 복사할 수 있습니다. `!심볼`을 사용하려면 Discord Developer Portal에서 Message Content Intent가 켜져 있어야 합니다.

`/명령어통계`는 전체·명령어별 사용 횟수와 사용자별 사용 횟수 상위 10명을 보여줍니다. 통계는 `state.json`에 저장되며 Discord 애플리케이션 소유자만 결과를 볼 수 있습니다. 다른 서버 관리자나 일반 사용자가 실행하면 통계 대신 권한 안내만 표시됩니다.

개인 계정에 설치해도 봇 프로그램은 Oracle 서버에서 계속 실행되어야 합니다.

## 실행하기

### 패치 수정 알림

- `/패치질문`은 사용자 요청으로 제거했습니다. 2026-09-09 배포·명령 동기화를 통해 운영 목록에서 제거했습니다. `/패치`와 패치 수정 알림은 유지합니다.
- 최신 패치 본문을 별도 작업으로 5분마다 비교합니다. `[Updated]` 제목만 바뀌고 본문이 같으면 보내지 않으며, 제목이 그대로여도 본문이 달라지면 `패치노트 추가 수정`을 기존 공지 채널에 전송합니다. 공지의 update 카테고리가 켜져 있어야 합니다.
- 첫 관측에는 비교 기준만 저장합니다. 그 이전 수정 내용은 복원할 수 없습니다. HTML 태그·공백만 달라진 변경은 무시합니다.
- `patch-history.db`에 비교 기준·변경분·요약·채널별 성공 기록을 보관합니다. 운영 백업에 포함하고 배포 시 덮어쓰지 않습니다. 일부 채널 실패는 다음 주기에 재시도합니다. 전송 직후 DB 기록 전 강제 종료되는 극히 짧은 구간에는 중복 가능성이 있습니다.
- 썬데이 표시에서는 Meso를 메소로 통일하고, 요청에 따라 스타포스 할인 제외 안내 한 줄과 중복 익몬 제외 한 줄을 숨깁니다. 실제 적용 조건은 공식 원문을 확인해야 합니다.

### 관리자 DM 번역교정 사용법

공지·패치 수정 알림과 별도 요약 테스트는 원문에 해당하는 교정표를 GPT에 전달합니다. 지정 한국어 용어를 사용하도록 지시하며, 실제 번역 품질은 결과 확인이 필요합니다. 썬데이·캐시샵의 Google 번역은 등록 용어를 임시 표식으로 보호한 뒤 권장 한국어로 복원하고 표식 누락·중복 시 전송하지 않습니다. `Arcane`은 아케인, `Arcane Umbra`는 아케인셰이드로 구분합니다. GPT에는 `Eternal/Dawn/Pitched`의 장비 문맥 제한을 함께 전달하며, Google은 바로 뒤에 equipment/gear/set/armor/weapon이 있을 때만 적용합니다.

사용자 확정 용어는 [API 번역 용어 교정표](TRANSLATION_GLOSSARY.md)에 정리합니다. 사용자 제공 GMS 직업·계열명과 아케인리버·그란디스 지역 및 스토리명도 포함합니다. 요약·번역 요청마다 해당 파일에서 원문에 등장하는 용어를 읽습니다. GPT에는 용어 지침으로 전달하고 Google에는 보호·복원 방식으로 적용합니다. 대소문자·연속 공백·아포스트로피 차이와 일반적인 s 복수형을 처리하고 긴 용어를 우선합니다. 파일을 DB로 복사하지 않으며 동일 용어는 아래 DM 교정값이 우선합니다. DM 목록·삭제는 DB 항목만 대상으로 하므로 DM 교정을 삭제하면 파일의 기본 표현이 다시 적용됩니다.

교정표 연결은 2026-09-09 운영에 적용했습니다. 향후에도 `translation_corrections.py`, `maple_bot.py`, `TRANSLATION_GLOSSARY.md`를 함께 유지해야 합니다. 코드 배포 후에는 서버 교정표 수정이 다음 API 요청부터 반영됩니다. 파일 누락·형식 오류는 번역 오류로 처리합니다. 추가 API 호출이나 재번역을 만들지 않으며 기존 결과를 강제 치환하지 않습니다. 등록 용어 외 번역의 정확성은 실제 출력 검토가 필요합니다.

봇 소유자(기존 백필 DM 관리자)가 봇 DM에 아래 내용을 **한 메시지**로 보낸 뒤, 3분 안에 `[저장]` 또는 `[취소]`를 누릅니다.

```text
번역교정
원문: Ring Polish Swap
잘못된 번역: 반지 폴리시 스왑
원하는 표현: 반지 연마 전수
```

- `번역교정`만 보내면 입력 안내를 표시합니다.
- `번역교정 목록`으로 등록 내용을 확인합니다.
- `번역교정 삭제 Ring Polish Swap`을 보내고 삭제 버튼으로 확인하면 해당 항목을 제거합니다.
- 같은 원문은 대소문자를 구분하지 않고 수정합니다. 각 항목은 1~200자, 최대 100개입니다.
- 교정은 `translation-corrections.db`에 저장됩니다. 재시작 후에도 유지되며 이 파일은 Git에 올리지 않고 운영 백업에 포함해야 합니다.
- 원문에 해당 용어가 있을 때만 GPT 용어 지침 또는 Google 표식 보호·복원을 적용하며 기존 발송 메시지·캐시·썬데이 고정 번역은 바꾸지 않습니다. 별도 테스트는 파일 사전만 사용하고 운영 봇은 동일 용어의 DM 교정값을 우선합니다.

### 공식 Discord 직접 수집

공지 색상은 일반 노랑·점검 및 기능 제한 주황·완료 및 정상화 초록입니다. 현재 구현은 취소선과 인사말을 제외한 원문의 첫 안내 문단으로 판별하므로 뒤쪽 문단에만 있는 상태 변경은 놓칠 수 있습니다.

2026-09-11 보조 1번의 브라우저 설치·직접 로그인·재실행 후 로그인 유지와 최신 공지 10개 추출을 확인했습니다. Ubuntu AppArmor에는 설치된 Chromium 실행 파일 하나에만 `userns`를 허용하는 규칙을 사용자 승인 후 적용했습니다. 브라우저 버전이 바뀌면 실행 경로와 규칙을 다시 확인해야 합니다. 보조 수집 서비스와 메인 자동 처리를 활성화했으며 최초 공지 10개는 재전송 없이 기준점으로 저장했습니다. 새 오픈 공지에 대한 실제 역할 멘션은 아직 발생하지 않았습니다.

공식 announcements(`309809230095843328`)만 보조 1번의 전용 Chromium 프로필로 읽습니다. 브라우저 화면의 메시지 ID·본문·링크·이미지·작성 시각을 2초마다 확인하며 브라우저 표시는 UTC로 고정합니다. 수집 파일은 별도 `discord-news-outbox`에서 기존 SSH 파일 전송 함수를 통해 메인의 `discord-news-inbox`로 전달합니다. 계정 토큰이나 쿠키를 추출하지 않습니다. 로그인 프로필·원본·수집 DB는 Git에 포함하지 않습니다.

보조 1번의 `discord-collector-code`에는 커밋된 저장소 코드를 별도로 배치합니다. 설치 승인 후 `sh discord-collector-code/deploy/prepare-discord-source.sh`로 별도 `.venv-discord`와 Chromium·시스템 의존성·로그인 화면 도구를 설치합니다. `sh discord-collector-code/deploy/login-discord-source.sh` 실행 후 SSH 로컬 포워딩으로 보조의 `127.0.0.1:6080`에 연결해 noVNC 화면에서 직접 로그인합니다. 공개 방화벽 포트를 열지 않습니다. 로그인은 첫 정상 채널 화면을 기록하면 종료됩니다. 브라우저 프로필은 같은 서버의 `discord-news-profile`에만 보관합니다.

보조의 버전 관리되지 않는 `discord-source.conf`에는 `DISCORD_NEWS_SYNC_TARGET=SSH별칭:/home/ubuntu/maplestory-discord-bot/discord-news-inbox`와 필요한 경우 `DISCORD_NEWS_SYNC_SSH_KEY`를 설정합니다. 랭킹 inbox를 목적지로 사용하면 안 됩니다. 서버별 SSH 설정은 실제 배포 시 확인해야 합니다. 서비스 예시는 `deploy/systemd/maple-discord-source.service`이며, 로그인·검증 전에 활성화하지 않습니다.

메인 봇은 `DISCORD_NEWS_MODE` 미설정 시 이 기능을 실행하지 않습니다. `shadow`는 최초 기준점·변경 기록만 보관하고 번역·공지를 게시하지 않으며, `live`는 이후 변경부터 기존 공지 채널에 보냅니다. `deploy/systemd/maple-discord-news-shadow.conf`는 검증 모드 예시입니다. 모드 변경 시 봇 재시작이 필요합니다. 수집 오류·3분 이상 미수신은 봇 소유자에게 상태 변화 시 알립니다.

단순히 이미 보낸 패치노트·캐시샵·점검 링크를 소개하는 명확한 짧은 문구만 중복으로 제외합니다. URL의 게시글 ID로 비교하며 제목 슬러그 변화는 무시합니다. 애매한 소개나 추가 정보는 전송하므로 의미상 중복을 전부 제거한다고 보장하지 않습니다. 번역이 10초를 넘기거나 실패하면 원문을 먼저 보내고 번역 완료 후 같은 메시지를 수정합니다. 긴 본문은 텍스트 첨부로 보존합니다. 이미지 전용 공지는 이미지와 원문 링크를 그대로 전달하며 이미지 안 글자의 자동 번역은 현재 하지 않습니다. 일반 본문 수정은 기존 메시지 편집, 명시적인 점검 완료·재개·연장 표현의 변화는 새 알림으로 처리합니다. 채널별 완료 기록으로 정상 재시도 중복을 막지만 Discord 전송 직후 DB 저장 전에 프로세스가 종료되는 경우 중복 가능성은 남습니다.

화면에 로드된 최근 메시지만 수정 감지 대상입니다. 오래된 메시지 수정, 장기 중단 중 화면 범위를 넘긴 글의 완전한 복구, Discord 연결 지연의 즉각 감지는 보장하지 않습니다. 계정 자동화 제재 가능성, 로그인 만료와 DOM 변경에 따른 중단 가능성이 있으며 로그인 만료·수신 중단은 관리자에게 알리며, 이때 서버 상태 API로 오픈 멘션을 대신 보내지 않습니다.

검증: `python -m unittest test_discord_news test_ranking_worker test_news_providers`. 서버 브라우저 1회 확인은 `.venv-discord/bin/python discord_news_collector.py --once`를 사용합니다.
