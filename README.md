# 메이플스토리 Discord 공지 봇

현재 버전: `v1.4.3`

메이플스토리 공식 홈페이지의 새 공지 중 `maintenance`, `sale`, `general`, `update`, `events` 카테고리를 Discord 채널에 알려주는 파이썬 봇입니다.

## 봇이 하는 일

1. 1분마다 메이플스토리 공식 뉴스 API에서 새 공지를 확인합니다. 이미 처리한 패치노트와 진행 중인 점검 공지의 본문은 5분마다 다시 확인합니다.
2. 새 공지의 영어 본문을 OpenAI가 3~5줄 영어 요약으로 만듭니다.
3. Google Cloud Translation이 그 짧은 요약을 한국어로 번역합니다.
4. 한국어 요약과 원문 링크를 관리자가 등록한 모든 Discord 채널에 보냅니다.
5. 공식 공지 목록의 썸네일을 Discord 임베드 이미지로 함께 보냅니다.
5. 이미 보낸 공지는 `state.json`에 기록해 다시 보내지 않습니다.

원문 전체를 번역하지 않고 요약만 번역하므로 번역 API 사용량을 줄일 수 있습니다.

실제 `update` 패치노트에 `Sunny Sunday` 표가 있으면 날짜별 혜택을 모두 추출해 전용 임베드 필드와 배너 이미지로 함께 보냅니다. 날짜는 Discord를 보는 사람의 현지 시간으로 표시됩니다. 반복 혜택은 지정된 한국어 표현을 사용하고, 새로운 보상 문구만 Google 번역으로 처리합니다. 제목이 `Preview`인 업데이트 소개 글에는 이 기능이 동작하지 않습니다.

번역된 Sunny Sunday 일정은 `state.json`에 저장됩니다. 각 일정의 시작 시각에는 등록된 당일 알림 채널 모두에 그 주 혜택을 보내고, 24시간 뒤 채널별 자동 메시지를 삭제합니다. `/썬데이`와 `/썬데이목록`은 외부 API를 다시 호출하지 않고 저장된 번역을 사용합니다.

Discord에서 `/썬데이`를 입력하면 현재 진행 중인 일정 또는 가장 가까운 다음 썬데이 메이플 한 건을, `/썬데이목록`을 입력하면 최신 패치노트에서 아직 지나지 않은 일정만 확인할 수 있습니다.

최신 패치노트의 `Cash Shop Transfer`와 `Miracle Time` 표도 `state.json`에 저장합니다. 이미 처리한 최신 패치노트도 5분마다 다시 읽으므로 넥슨이 본문을 나중에 수정해 일정을 추가해도 반영됩니다. `/캐시이동`은 캐시 보관함 이동 시작·종료 시간을, `/미라클큐브`는 남아 있는 날짜별 미라클 타임 대상 장비를 보여줍니다.

`/캐샵`은 최신 공식 `Cash Shop Update` 공지와 캐시샵 데이터 마이닝 페이지 링크를 함께 보여줍니다. 새 `sale` 카테고리의 `Cash Shop Update`가 올라오면 공지 확인 작업이 링크를 `state.json`에 자동 갱신합니다. 다른 판매 공지는 최신 캐시샵 링크를 덮어쓰지 않습니다.

`/패치` 또는 `!패치`는 1분 공지 감시에서 확인한 최신 실제 패치노트의 정리된 제목과 공식 링크를 보여줍니다. 수정일 접두사와 `Patch Notes` 접미사는 제목에서 생략하며 Discord가 공식 사이트 썸네일 미리보기를 자동으로 표시합니다.

`/항해` 또는 `!항해`는 GMS 항해 가이드 이미지를 임베드 없이 바로 보여줍니다.

`/핫위크`와 `/큐브세일`은 향후 패치노트 수집을 연결하기 위한 명령어이며, 현재는 진행 중인 이벤트가 없다는 안내만 표시합니다.

## 우르스 골든타임 명령어

`/우르스`는 UTC 01:00~05:00와 18:00~22:00를 기준으로 골든타임 진행 여부를 자동 판별합니다. 미국 서부시간으로는 서머타임에 오전 11시~오후 3시와 오후 6시~오후 10시, 표준시간에 오전 10시~오후 2시와 오후 5시~오후 9시입니다. 임베드의 시각은 Discord 타임스탬프로 표시되어 각 사용자의 현지시간으로 자동 변환됩니다.

관리자가 `/우르스알림`을 켜면 각 골든타임의 시작과 종료 시각에만 알림을 보냅니다. 시작 알림에는 컬러 이미지를, 종료 알림에는 흑백 이미지를 사용하며 중간 시간이나 봇 재시작 시에는 뒤늦은 알림을 보내지 않습니다.

## 메이플 서버 상태 명령어

`/서버`는 넥슨 공식 서버 상태 API에서 글로벌 메이플의 주요 상시 월드인 `Scania`, `Bera`, `Kronos`, `Hyperion`을 확인합니다. 네 월드 모두 로그인 서버가 정상이고 게임 채널이 하나 이상 열려 있을 때 전체 서버를 정상으로 표시합니다. 계절 서버와 상태 데이터가 없는 테스트 서버는 판정에서 제외합니다.

관리자가 `/서버알림`을 켜면 공식 점검 공지의 일정을 `state.json`에 저장합니다. 종료 시각이 있는 점검은 종료 1시간 전(점검 시작이 더 늦으면 시작 시각)부터 1분마다 상태를 확인하고, 종료 시각이 없는 긴급점검은 공지를 발견한 즉시 확인합니다. 주요 월드가 정상으로 돌아오면 채널별로 설정한 역할을 멘션해 한 번 알린 뒤 다음 점검까지 서버 상태 API 호출을 멈춥니다. 공식 API 오류는 서버 오픈으로 판단하지 않습니다.

점검 시작 직후 서버가 잠깐 정상으로 잡히는 상황은 오픈으로 오인하지 않습니다. 실제 점검 상태를 확인한 뒤 정상으로 바뀌거나, 예정 종료 시각 이후 정상으로 확인될 때 알립니다. 종료 시각이 없는 긴급점검은 반드시 점검 상태를 한 번 확인한 뒤 정상으로 바뀌었을 때만 알립니다. `/서버` 명령어는 자동 감시와 별개로 언제든 현재 상태를 즉시 확인합니다.

## 시간·환율 채널

`/시간` 또는 `!시간`은 UTC와 미국 서부·중부·동부, 유럽, 한국, 호주의 현재 날짜와 시각을 한 임베드로 보여줍니다. 각 지역의 서머타임과 `PDT`·`PST` 같은 표기는 시간대 데이터에 따라 자동으로 바뀝니다.

관리자가 `/정보채널`에서 종류와 음성 채널을 고르면 채널 이름을 자동으로 갱신합니다. 시간과 네이버 금융의 USD/KRW 매매기준율은 10분마다 갱신합니다. 시간 채널은 Discord의 채널 이름 변경 제한을 피하기 위해 5분보다 짧게 갱신하지 않습니다. 환율 페이지를 읽지 못하면 기존 채널 이름을 유지하고 다음 주기에 다시 시도합니다.

UTC 시각은 별도의 `/utc채널`로 설정하며 `UTC: 19:30` 형식으로 표시합니다.

```text
/정보채널 종류:시간 채널:#시간 동작:ON
/정보채널 종류:환율 채널:#환율 동작:ON
/utc채널 채널:#UTC 동작:ON
```

텍스트 채널에서 환율의 변경 과정도 확인하려면 관리자가 `/환율기록알림`을 사용합니다. 한국시간 날짜별로 메시지 하나만 만들고 10분마다 환율이 실제로 달라졌을 때만 기존 메시지를 수정합니다. 최근 변동은 5개만 표시하며 상승은 `🔴 ▲`, 하락은 `🔵 ▼`로 구분합니다. 기록과 메시지 ID는 `state.json`에 저장되어 봇을 재시작해도 이어집니다.

```text
/환율기록알림 채널:#환율기록 동작:ON
```

봇에는 선택한 음성 채널의 `채널 보기`와 `채널 관리` 권한이 필요합니다. `OFF`는 자동 갱신만 멈추며 현재 채널 이름은 그대로 둡니다.

## 글로벌 리부트 보스 5% 명령어

`/5퍼`에서 보스와 난이도를 선택하면 해당 보스의 총 체력과 보상을 받기 위해 전투력 분석에 기록해야 하는 5% 최소 피해량을 인게임 전투분석과 같은 K 단위로 보여줍니다. `검밑`을 선택하면 스우·데미안·루시드·윌·더스크·진 힐라·듄켈의 대표 난이도 수치를 한 번에 보여주므로 난이도를 따로 입력하지 않아도 됩니다. 그 외 보스에서 존재하지 않는 난이도를 고르면 선택 가능한 난이도를 안내합니다.

## 알림 채널 설정 명령어

아래 명령어는 서버 관리자만 실행할 수 있습니다. `채널`에서는 현재 서버의 텍스트 채널을 선택하고, `동작`에서는 `ON` 또는 `OFF`를 선택합니다. 같은 알리미에 여러 채널을 등록할 수 있습니다.

```text
/공지알림 채널:#공지 동작:ON
/썬데이알림 채널:#메인채팅 동작:ON
/썬데이목록알림 채널:#썬데이메이플 동작:ON
/미라클큐브알림 채널:#메인채팅 동작:ON
/캐시이동알림 채널:#메인채팅 동작:ON
/우르스알림 채널:#메인채팅 동작:ON
/서버알림 채널:#메인채팅 동작:ON 역할:@메이플알림
/서버알림 채널:#메인채팅 동작:OFF
/큐브세일알림 채널:#메인채팅 동작:ON
```

- `/공지알림`: `maintenance`, `sale`, `general`, `update`, `events` 번역 공지
- `/썬데이알림`: 해당 주 Sunny Sunday가 시작될 때 보내고 24시간 뒤 삭제하는 당일 알림
- `/썬데이목록알림`: 새 패치노트에서 전체 Sunny Sunday 목록을 발견했을 때 보내는 알림
- `/미라클큐브알림`: 각 미라클 타임 날짜의 UTC 00:00부터 채널별로 한 번 보내는 당일 알림
- `/캐시이동알림`: 캐시이동 시작 시각부터 24시간 안에 채널별로 한 번 보내는 당일 알림
- `/우르스알림`: 미국 서부의 서머타임을 자동 적용해 골든타임 시작·종료 시각에 보내는 알림
- `/서버알림`: 점검 종료 감시 중 주요 4개 월드가 정상으로 돌아오면 설정한 역할을 멘션하는 서버 오픈 알림
- `/큐브세일알림`: 향후 큐브세일 자동 알림을 받을 채널을 미리 저장하는 설정

이미 `ON`인 채널을 다시 켜도 중복 전송하지 않습니다. 목록 알림을 새 채널에 처음 켜면 `state.json`에 저장된 최신 전체 목록을 그 채널에 한 번 보내며, 이후에는 다음 패치노트의 새로운 목록이 나올 때까지 다시 보내지 않습니다.

서버 오픈 알림은 채널마다 서로 다른 역할을 설정할 수 있습니다. 역할이 멘션 가능 상태가 아니면 봇에 `모두 멘션하기` 권한이 있어야 실제 알림이 울립니다.

## HEXA 강화 계산 명령어

Discord에서 `/헥사`를 입력하고 코어 종류, 현재 레벨, 목표 레벨을 선택하면 필요한 솔 에르다와 솔 에르다 조각 합계를 계산합니다.

```text
/헥사 코어종류:강화 코어 현재레벨:7 목표레벨:20
```

지원하는 코어 종류는 `스킬 코어`, `3rd 스킬 코어`, `마스터리 코어`, `강화 코어`, `공용 코어`, `직업군 공용 코어`입니다.
현재 레벨은 0~29, 목표 레벨은 1~30 범위에서 선택할 수 있습니다.

## 채널 추천 명령어

Discord에서 `/채널추천`을 입력하면 메이플스토리 게임 채널 1~40 중 하나를 무작위로 추천합니다. 명령어를 실행한 사용자의 Discord 닉네임과 추천 채널을 20가지 안내 문구 중 하나로 무작위로 보여주며, 닉네임 끝 글자의 받침에 따라 `아`와 `야`를 자연스럽게 구분합니다.

## PSSB 시뮬레이터

Discord에서 `/스스비`를 입력하고 `1회` 또는 `5회`를 선택하면 현재 공식 Premium Surprise Style Box 확률표로 결과를 추첨합니다. 명령어 실행과 `다시 뽑기` 버튼 클릭 때마다 공식 표를 새로 읽으므로 구성품 변경을 코드에 직접 입력할 필요가 없습니다.

이 명령어는 Discord 언어가 한국어일 때 `/스스비`로 표시되며 `/ssb`로 검색할 수 있습니다. 초성 별칭 `/ㅅㅅㅂ`도 같은 기능을 실행합니다.

성별 아이템 두 개가 확률 하나를 공유하면 한 보상으로 합쳐 표시하며, 각 추첨은 독립적이므로 같은 아이템이 중복으로 나올 수 있습니다. 1회와 5회 모두 메시지 한 개로 전송하며, 5회 결과는 실제 GMS SSB처럼 아이콘 다섯 개가 가로로 놓인 이미지 한 장으로 표시합니다. 확률이 2.00% 이하인 아이템은 보라색 슬롯과 `✨` 표식, 2.00%를 초과하는 아이템은 회색 슬롯을 사용합니다. 임베드 아래에는 처음 실행부터 `다시 뽑기`까지 사용한 누적 상자 수를 표시합니다.

`기대값 계산하기` 버튼을 누르면 현재 결과 아이템의 공식 등장 확률, 평균적으로 필요한 상자 수, 평균 구매 비용과 내 누적 상자 수 안에 한 번 이상 얻을 확률을 보여줍니다. 구매 비용은 낱개 3,600 NX와 11개 세트 36,000 NX 중 가장 저렴한 조합으로 계산합니다. 같은 아이템이 중복된 결과에서는 한 번만 계산합니다. `다시 뽑기`와 기대값 버튼은 처음 명령어를 실행한 사용자만 누를 수 있습니다.

배경 광원과 슬롯은 GMS 클라이언트 리소스를 사용하고, 아이템 아이콘은 로컬 WZ 데이터베이스에서 영문명이 정확히 연결되는 일반 장비에 표시합니다. 데이터베이스에 없거나 독립 아이콘이 없는 아이템도 빈 슬롯과 결과 이름은 남습니다.

## 퍼밀리어 잠재능력 시뮬레이터

Discord에서 `/퍼밀리어`를 입력하면 유니크 등급 퍼밀리어 카드의 잠재능력 두 줄을 무작위로 추첨합니다. 첫 번째 줄은 항상 유니크이며, 두 번째 줄은 99% 확률로 에픽, 1% 확률로 유니크가 나옵니다. 두 번째 줄도 유니크가 나오면 `더블 프라임`으로 표시합니다.

옵션과 가중치는 사용자가 제공한 커뮤니티 표본 확률표를 사용합니다. 표본에서 한 번도 나오지 않은 `보스 몬스터 공격 시 데미지 +35%`는 추첨에서 제외했습니다. 같은 옵션이 두 줄에 중복으로 나올 수 있습니다.

결과는 GMS 클라이언트에서 추출한 실제 퍼밀리어 상세 카드 UI에 잠재능력 두 줄을 넣은 이미지 한 장으로 표시합니다. 시뮬레이터의 고정 기본 외형은 캐시 펫 `Sherbet`이며, 등급은 유니크·레벨은 1로 표시합니다. 한글 렌더링에는 SIL Open Font License 1.1의 나눔고딕을 사용합니다.

결과의 `다시 뽑기` 버튼을 누르면 같은 메시지의 잠재능력과 카드 이미지를 다시 추첨하며, 이미지와 함께 누적 횟수를 표시합니다. 봇은 시작할 때 가능한 4,784개 조합의 확률·평균 기대 횟수와 현재 조합만큼 희귀하거나 더 희귀한 결과가 실제로 나올 확률을 `familiar.db`에 미리 저장합니다. `기대값 계산하기` 버튼은 현재 조합 한 건을 DB에서 읽고 내 누적 횟수 안에 이 결과를 얻을 확률도 함께 보여주며 누구나 사용할 수 있습니다. `다시 뽑기`는 처음 명령어를 실행한 사용자만 누를 수 있고 두 버튼 모두 24시간 동안 유효합니다.

## 시드링 강화 시뮬레이터

`/시드링`에서 리스트레인트 링의 현재 레벨과 연마석 1~5개를 선택하면 한 번의 강화 결과를 추첨합니다. Lv.4에서는 생명의 연마석 한 개당 10%, Lv.5에서는 신념의 연마석 한 개당 5%의 성공 확률을 적용합니다.

```text
/시드링 현재레벨:Lv.4 → Lv.5 연마석개수:5개
```

결과 아래의 `같은 조건으로 다시 시도` 버튼을 누르면 같은 메시지에서 독립적으로 다시 추첨합니다. 시도 횟수, 성공·실패 횟수와 누적 사용 연마석이 함께 표시되며 버튼은 명령어를 실행한 사용자만 사용할 수 있습니다.

Discord에서 `/아이템검색`을 입력한 뒤 영문명, 한글명 또는 아이템 ID를 입력하면 자동완성 목록에서 캐시 아이템을 고를 수 있습니다. 결과에는 GMS 이름, KMS 이름, 분류와 아이템 ID를 표시하며 독립 아이콘이 있는 장비는 아이콘도 함께 보여줍니다.

## 외형 검색

Discord에서 `/외형검색`을 입력한 뒤 `헤어` 또는 `성형`을 고르고 영문명, 한글명 또는 외형 ID를 입력하면 해당 종류만 자동완성 목록에 표시합니다. 결과에는 GMS 이름과 같은 ID의 KMS 이름을 함께 보여줍니다. 헤어와 성형은 독립 아이콘이 없어 이름만 표시합니다.

검색 데이터에는 제공받은 GMS의 캐시 장비 전체가 들어 있습니다. 같은 아이템 ID가 KMS에도 있으면 한글명을 함께 표시하고, 없으면 `KMS 동일 ID 없음`으로 표시합니다. 양쪽 서버에서 이름은 같지만 ID가 다른 아이템은 자동으로 같은 아이템이라고 판단하지 않습니다. 헤어와 성형은 캐릭터 위에 여러 이미지를 합성하는 데이터라 현재는 이름만 표시합니다.

## 캐시 아이템 DB 업데이트하기

GMS 또는 KMS가 패치되면 **봇 프로젝트 폴더에서** 다음 명령을 한 번 실행합니다. 게임 파일 수만 개를 읽기 때문에 몇 분 걸릴 수 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\update_cash_item_db.ps1
```

기본 게임 폴더가 다른 경우에만 경로를 직접 적습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\update_cash_item_db.ps1 `
  -GmsDataPath "D:\SteamLibrary\steamapps\common\MapleStory\Data" `
  -KmsDataPath "C:\KMS\Maple\Data"
```

도구는 새 `cash-items.tsv`와 `cash-item-icons.zip`을 임시 폴더에서 먼저 완성하고, 아이템·아이콘 개수가 정상인지 확인한 뒤 `data` 폴더의 기존 파일을 교체합니다. `Item` 폴더는 현재 캐시 장비 검색에는 필요하지 않으며, GMS·KMS의 `String` 폴더와 GMS의 `Character` 폴더를 사용합니다.

완료 후 `python -m unittest`를 실행해 봇 테스트가 통과하는지 확인하고 Git에 올리면 됩니다. 이 작업은 Oracle 서버가 아니라 게임 파일이 설치된 Windows 컴퓨터에서 실행합니다.

## 성장의 비약 계산기

Discord에서 `/성장의비약`을 입력하고 비약 종류, 시작 레벨, 현재 경험치 퍼센트, 버닝 여부, 사용할 개수를 입력하면 사용 후 레벨과 경험치를 계산합니다. 시작 레벨은 **200~299**만 입력할 수 있습니다.

```text
/성장의비약 비약종류:극성비 · 극한 성장의 비약 시작레벨:245 경험치:37.5 하이퍼버닝:미적용 비욘드버닝:미적용 개수:3
```

현재 지원하는 비약은 익성비, 궁성비, 극성비, 초성비, 전성비입니다. 각 비약의 보장 구간에서는 현재 레벨에 필요한 경험치를 지급하고, 구간을 넘으면 사용자가 제공한 최신 표의 고정 경험치를 지급합니다. 130~199 구간의 익성비 무작위 레벨 상승은 `/익성비`에서, 레벨 200 이상 고정 경험치는 `/성장의비약`에서 계산합니다.

하이퍼 버닝은 한 번 레벨업할 때 5레벨씩 오르되 Lv.260에서 정확히 끝나며, 비욘드 버닝은 Lv.260부터 2레벨씩 오르되 Lv.270에서 정확히 끝납니다. 경험치 퍼센트를 실제 경험치로 환산하므로 소수점 반올림에 따라 실제 게임과 아주 조금 다를 수 있습니다.

## EXP 교환권 계산기

Discord에서 `/exp쿠폰`을 입력하면 일반 EXP 교환권 또는 상급 EXP 교환권을 입력한 개수만큼 사용했을 때의 최종 레벨과 경험치를 계산합니다.

```text
/exp쿠폰 쿠폰종류:상급 EXP 교환권 시작레벨:270 경험치:15.5 개수:10000 버닝:X
```

제공받은 최신 표를 기준으로 일반 EXP 교환권은 Lv.200~260, 상급 EXP 교환권은 Lv.260~299에서 계산합니다. 버닝은 `X`, `하이퍼버닝`, `비욘드버닝` 중 하나를 선택하며 각각 Lv.260과 Lv.270에서 정확히 끝납니다. 버닝을 생략하면 사용자별로 마지막에 선택한 값을 다시 사용하고, 저장된 값이 없는 첫 사용자는 `X`를 기본으로 적용합니다. 선택값은 봇이 재시작되어도 유지되도록 Discord 사용자 ID와 함께 `state.json`에 저장합니다. 결과 제목에는 일반 교환권은 EV, 상급 교환권은 AEV 커스텀 이모지를 표시합니다. 사용 가능한 마지막 레벨을 넘거나 Lv.300에 도달하면 남은 교환권은 적용하지 않습니다.

## 에픽 던전 경험치 계산 명령어

`/에픽던전`에서 던전, 현재 레벨, 현재 경험치 퍼센트, 경험치 보너스를 선택하면 완료 후 레벨과 경험치를 계산하고 솔 에르다 보상을 함께 표시합니다.

```text
/에픽던전 던전:앵글러컴퍼니 레벨:275 경험치:30 경험치보너스:2배
```

- 하이마운틴: Lv.260 이상
- 앵글러컴퍼니: Lv.270 이상
- 악몽선경: Lv.280 이상
- 경험치 보너스: 1.5배, 2배, 2.5배

Lv.294 이상은 각 표의 마지막 고정 경험치를 사용하며, 계산 결과는 Lv.300에서 멈춥니다.

## 아케인·어센틱 심볼 계산기

`/심볼계산기`에서 지역, 현재 레벨·성장치, 목표 레벨, 보약 레벨과 엘라노스 적용 여부를 선택하면 추가로 필요한 심볼 개수와 강화 메소, 일일 퀘스트 기준 예상 완료일을 계산합니다. 심볼 종류는 선택한 지역으로 자동 판별합니다. 보약 레벨과 엘라노스를 생략하면 사용자별 마지막 선택값을 사용하며, 저장값이 없는 첫 사용은 보약 없음·엘라노스 미적용을 기본으로 적용합니다. 선택값은 Discord 사용자 ID와 함께 `state.json`에 저장되어 봇 재시작 후에도 유지됩니다.

```text
/심볼계산기 지역:세르니움 현재레벨:3 현재성장치:50 목표레벨:11 보약레벨:6레벨 엘라노스:적용
```

- 아케인 심볼: 일일 기본 20개, 최대 Lv.20
- 어센틱·그랜드 어센틱 심볼: 일일 기본 10개, 최대 Lv.11
- 보약: 없음 또는 1~6레벨
- 엘라노스 적용: `(기본 심볼 + 보약 보너스) × 120%`의 소수점을 버립니다.
- 엘라노스 미적용: `기본 심볼 + 보약 보너스`를 지급량으로 사용합니다.
- 아케인 심볼: 일일퀘만 수행한 경우와 지역별 주간퀘 120개를 이번 주에 수행한 경우·수행하지 않은 경우를 함께 표시합니다.

선택한 조건은 2026년 9월 8일 23:59 UTC까지만 계산하며, 이후에는 보약과 20% 추가 지급을 제외한 기본 심볼 개수만 적용합니다. 예상 완료일은 명령어를 실행한 날의 일일 퀘스트와 이번 주 주간 퀘스트를 아직 받지 않은 성장치로 계산합니다. 주간퀘 120개에는 엘라노스와 보약 보너스를 적용하지 않습니다.

## GMS 캐릭터 랭킹

`/랭킹 닉네임`은 넥슨 공식 북미 GMS 랭킹에서 캐릭터를 찾아 캐릭터 이미지, 레벨·경험치 진행률, 직업·월드, 전체·월드·유니온·업적 순위, 메이플 종합 지수와 태그를 임베드 없이 한 장의 이미지로 보여줍니다. 자동 수집하거나 직접 조회한 캐릭터의 날짜별 경험치를 `ranking.db`에 30일간 저장하며, 7일·14일·30일의 일평균과 누적 획득 경험치, 최근 14일치 경험치 변화를 청회색·하늘색·라임 색상의 이미지 그래프로 함께 표시합니다. 그래프 왼쪽에는 최고 경험치에 맞춰 자동 조절되는 `T` 단위 기준 눈금이 표시됩니다.

```text
/랭킹 닉네임:Home
```

한 번 닉네임을 입력해 조회하면 그 Discord 계정의 기본 캐릭터로 기억합니다. 이후에는 `/랭킹`만 입력해도 마지막으로 등록한 캐릭터를 다시 조회합니다. 다른 캐릭터를 조회하면 기본값도 그 이름으로 바뀝니다.

유니온과 업적은 계정의 대표 캐릭터만 공식 랭킹에 표시됩니다. `/랭킹`은 저장된 대표 캐릭터 데이터만 즉시 사용하며, 명령어 실행 중에는 대표 여부를 확인하는 추가 요청을 보내지 않습니다. 저장된 유니온·업적이 모두 없는 캐릭터는 `부캐` 태그와 `대표 캐릭터에서만 확인 가능` 안내를 표시하고, 우선 수집기가 백그라운드에서 다음 갱신을 처리합니다.

**메이플 종합 지수**는 0.00~99.90점의 재미용 종합 점수입니다. 캐릭터 성장(레벨·경험치·전체 순위) 40점, 유니온(레벨·순위) 30점, 업적(점수·순위) 30점을 합산합니다. 세 랭킹이 모두 1위면 99.90점으로 고정합니다. 이미지에는 점수 단계, 균형 여부, 가장 높은 분야를 조합해 `메이플 마스터`·`균형의 달인`·`레벨 장인`처럼 최대 3개의 태그를 표시합니다.

공식 GMS 랭킹 화면의 공개 응답을 사용하므로 넥슨 사이트 구조가 바뀌거나 갱신 중이면 잠시 결과가 나오지 않을 수 있습니다.
외부 랭킹 사이트의 과거 기록을 가져오지 않으므로 처음 조회한 날에는 기록 시작 안내만 표시됩니다. 같은 날짜에 다시 조회하면 그날 기록을 최신 값으로 교체합니다.

북미 주요 4개 월드(Scania·Bera·Kronos·Hyperion)의 기록은 1초마다 1페이지, 최대 10명씩 자동 수집합니다. `/랭킹` 조회 캐릭터를 먼저 갱신하고, 최근 7일 안에 레벨·경험치가 변했거나 아직 7일치 기록이 없는 캐릭터가 포함된 페이지를 높은 순위부터 처리합니다. 7일 이상 페이지 전원의 경험치가 그대로인 페이지는 그 뒤에 월드별 상위 순위부터 수집합니다. 공식 API가 403을 보내면 5분·15분·1시간·최대 6시간, 429를 보내면 1분부터 최대 1시간까지 단계적으로 API 호출을 건너뛴 뒤 같은 순위부터 다시 시도합니다. 정상 응답이 한 번 나오면 대기 단계가 초기화됩니다. 서버가 재시작되어도 대기 상태와 월드별 수집 순번을 유지하며 밀린 요청을 한꺼번에 보내지 않습니다. 각 월드에서 Lv.260 미만을 만나면 그 월드의 당일 수집을 마칩니다.

### 수집기 2대 분산 실행

두 번째 수집기는 같은 서버에서 실행하지 않고 별도 공인 IP의 Oracle 인스턴스에서 `python ranking_worker.py`로 실행합니다. 메인 서버와 보조 수집기는 서로 다른 월드를 담당하면서 각각 1초당 1페이지의 요청 시작 제한을 지킵니다. 느린 API 응답 때문에 요청 간격이 늘어나지 않도록 응답은 기본 3개까지 겹쳐 기다리며 `RANKING_WORKER_CONCURRENCY`로 조절할 수 있습니다. 운영 `ranking.db`는 메인 서버만 쓰며, 보조 수집기는 60페이지를 원자적인 JSONL 묶음으로 만든 뒤 SSH로 `ranking-inbox`에 전송합니다. 메인 봇은 전송이 끝난 파일만 백그라운드에서 합치고 `processed`로 옮깁니다. 늦게 도착한 과거 묶음은 날짜별 기록만 채우며 더 최신인 캐릭터 현재값을 되돌리지 않습니다.

MapleBot 과거 경험치 백필은 보조 서버에서 체크포인트와 현재 레벨을 남기며 실행합니다. 그래프와 무관한 이미지·폰트·미디어는 받지 않으며, 정상 프로필에 경험치 그래프가 없는 캐릭터도 체크포인트에 기록해 재시작 때 다시 조회하지 않습니다. 오류로 종료되면 5초 후 같은 레벨부터 자동 재실행합니다. 봇 소유자는 봇과의 Discord DM에서 `백필 상태` 또는 `백필 확인`으로 진행량을 확인하고 `백필 재시작`으로 수동 재시작할 수 있으며 띄어쓰기는 생략해도 됩니다. 메인 서버에는 `BACKFILL_CONTROL_HOST`, `BACKFILL_CONTROL_SSH_KEY`를 설정하며 해당 키는 보조 백필 서버에만 접속할 수 있는 전용 키를 사용합니다.

예를 들어 인원이 가장 많은 Kronos를 메인 서버가 맡고 나머지 세 월드를 보조 서버가 맡으려면 메인 서버에는 `RANKING_WORLD_IDS=45`, 보조 서버에는 `RANKING_WORKER_WORLD_IDS=19,1,70`을 설정합니다. 보조 서버의 `RANKING_SYNC_TARGET`에는 메인 서버의 `ranking-inbox` SSH 경로를, `RANKING_SYNC_SSH_KEY`에는 전송 전용 키 경로를 설정합니다. 메인 서버의 `processed`와 보조 서버의 `sent` 묶음은 복구 확인 전까지 자동 삭제하지 않습니다.

`/랭킹`으로 조회에 성공한 캐릭터는 중복 없이 우선 대상에 등록됩니다. 다음 날짜의 자동 수집에서는 이 캐릭터들을 최근 조회 순서로 하루 한 번 먼저 갱신한 뒤 월드별 상위 랭킹 수집을 이어갑니다. 명령어 조회와 자동 수집을 포함한 모든 공식 랭킹 요청은 같은 요청 간격 제한을 공유합니다.

수집 데이터는 페이지마다 즉시 `ranking.db`에 저장합니다. 별도 백업은 일일 랭킹 수집을 마친 뒤 프로젝트 밖 `~/maplestory-discord-bot-backups/ranking.db`에 만들고 SQLite 무결성 검사를 실행합니다. 자동 수집을 켜지 않아도 `/랭킹`으로 직접 조회한 기록은 같은 DB에 저장됩니다.

공식 랭킹의 실제 일일 갱신 시각을 측정할 때는 `python tools/probe_ranking_update.py`를 실행합니다. 최근 경험치 변경 캐릭터 5명을 10분마다 확인하고 최초 변경 감지 시각을 한국시간으로 `ranking-update-probe.json`에 남긴 뒤 종료합니다. 기본 감시 시간은 24시간입니다.

## 명령어 도움말

`/명령어`는 일반 사용자가 쓸 수 있는 계산기, 시뮬레이터와 일정 확인 명령어를 한 화면에 보여줍니다. 안내는 명령어를 실행한 사용자에게만 표시됩니다.

`/ㅁ`, `/심볼`, `!심볼`은 `Sacred Symbol/claim`, `Arcane Symbol/claim`, `Sol Erda Fragment`, `/partyleave`를 각각 별도의 코드 블록으로 보여줍니다. PC에서는 각 코드 블록의 복사 버튼을 누르고, 모바일에서는 코드 블록을 길게 눌러 복사할 수 있습니다. `!심볼`을 사용하려면 Discord Developer Portal에서 Message Content Intent가 켜져 있어야 합니다.

`/명령어통계`는 전체·명령어별 사용 횟수와 사용자별 사용 횟수 상위 10명을 보여줍니다. 통계는 `state.json`에 저장되며 Discord 애플리케이션 소유자만 결과를 볼 수 있습니다. 다른 서버 관리자나 일반 사용자가 실행하면 통계 대신 권한 안내만 표시됩니다.

### 개인 Discord 계정에 명령어 설치하기

공지 자동 전송은 기존처럼 지정한 서버 채널에서만 동작하고, `/명령어`, `/랭킹`, `/ㅁ`, `/심볼`, `/헥사`, `/채널추천`, `/시드링`, `/스스비`, `/퍼밀리어`, `/익성비`, `/성장의비약`, `/exp쿠폰`, `/에픽던전`, `/심볼계산기`, `/아이템검색`, `/외형검색`, `/5퍼`, `/캐샵`, `/캐시이동`, `/우르스`, `/서버`, `/미라클큐브`, `/핫위크`, `/큐브세일` 명령어는 개인 계정에 설치해 서버와 DM에서 사용할 수 있습니다.

1. Discord Developer Portal의 `Installation`에서 `사용자 설치`와 `길드 설치`를 모두 켭니다.
2. 비공개 애플리케이션은 `설치 링크`를 `없음`으로 둡니다.
3. `OAuth2`의 URL 생성기에서 `applications.commands`와 `User Install`을 선택합니다.
4. 생성된 링크를 열고 `내 앱에 추가`를 선택합니다.

개인 계정에 설치해도 봇 프로그램은 Oracle 서버에서 계속 실행되어야 합니다.

## 프로젝트 파일 구조

- `maple_bot.py`: Discord 명령어, 공지 크롤링, 봇 실행 코드

- `data/cash-items.tsv`: GMS 캐시 아이템과 동일 ID가 있는 KMS 한글 이름
- `data/cash-item-icons.zip`: 검색 결과에 첨부하는 캐시 장비 아이콘
- `tools/update_cash_item_db.ps1`: 패치된 WZ 파일에서 위 두 데이터 파일을 다시 만드는 도구
- `tools/wz_cash_exporter`: WZ 파일을 읽는 추출기와 WzComparerR2 MIT 라이선스 안내

## 처음 설치하기

PowerShell을 열고 프로젝트 폴더로 이동합니다.

```powershell
cd "D:\Code\파이썬\maplestory-discord-bot"
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

생성된 `.env` 파일을 메모장으로 열고 아래 다섯 값을 실제 값으로 바꿉니다.

```env
DISCORD_TOKEN=Discord_봇_토큰
DISCORD_CHANNEL_ID=알림을_보낼_채널_ID
SUNNY_SUNDAY_CHANNEL_ID=Sunny_Sunday_전용_채널_ID
OPENAI_API_KEY=OpenAI_API_키
GOOGLE_TRANSLATE_API_KEY=Google_번역_API_키
```

기존 설치를 안전하게 이전하기 위해 처음 한 번은 `DISCORD_CHANNEL_ID`를 공지 알림으로, `SUNNY_SUNDAY_CHANNEL_ID`를 썬데이 당일·목록 알림으로 등록합니다. 이후 채널 설정은 `state.json`에 저장되며 위의 관리자 명령어로만 변경됩니다. `SUNNY_SUNDAY_CHANNEL_ID`가 비어 있으면 두 썬데이 알림도 기존 `DISCORD_CHANNEL_ID`에서 시작합니다.

## 실행하기

```powershell
python maple_bot.py
```

처음 실행할 때는 기존 공지를 보내지 않습니다. 그 시점의 공지 목록을 기준으로 저장한 뒤, 이후에 올라오는 새 글만 알립니다.

## 파일 설명

- `maple_bot.py`: 봇의 실제 동작 코드
- `.env`: 내 API 키와 Discord 설정을 보관하는 개인 파일. 공유하면 안 됨

- `data/cash-items.tsv`: 캐시 아이템 영문명·한글명 검색 데이터
- `data/cash-item-icons.zip`: 캐시 아이템 아이콘 묶음
- `assets/familiar-*.png`: GMS 퍼밀리어 카드 UI와 Sherbet 표시용 이미지
- `assets/NanumGothic.ttf`: 퍼밀리어 결과 이미지의 한글 표시용 나눔고딕
- `CHANGELOG.md`: 수정한 내용 기록
