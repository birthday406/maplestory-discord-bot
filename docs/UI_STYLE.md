# Discord 응답 양식

이 문서는 뽀찌 봇의 명령어·자동 공지 응답을 만들거나 수정할 때 따르는 기준입니다.
대화가 요약되거나 새 작업이 시작되어도 먼저 이 문서와 `PROJECT_RULES.md`를 읽습니다.
사용자가 새로 결정한 내용은 이 문서에 반영합니다. 과거 시안이나 현재 코드가 이 기준과 다르면 최신 사용자 결정을 우선합니다.

## 1. 기본 방향: 간결형 A안

- 제목 → 대상·조건 → 결과 순서로 읽히게 합니다.
- 짧은 정보는 `항목　값`으로 표시합니다. 공백을 여러 개 넣어 열을 억지로 정렬하지 않습니다.
- 중요한 결과값과 긴 내용의 항목명만 굵게 표시합니다. 본문 전체를 굵게 만들지 않습니다.
- 같은 항목의 제목과 설명은 바로 다음 줄에 붙입니다. 내용 묶음 사이에만 빈 줄 하나를 둡니다.
- 큰 숫자를 별도 제목으로 만드는 B안은 사용하지 않습니다.
- 짧은 결과마다 소제목·필드를 추가하지 않습니다. 긴 공지·일정은 항목 구분이 필요할 때 필드를 사용합니다.
- 반복되는 요약, `핵심`, 장식용 `◆`, 긴 구분선은 추가하지 않습니다.

## 2. 이모지는 의미가 있는 기존 자산 우선

**양식 통일은 모든 이모지를 별로 바꾸는 작업이 아닙니다.**

| 위치·종류 | 규칙 |
| --- | --- |
| HEXA, 성장의 비약, EXP 교환권, 에픽 던전 등 기존 전용 이모지가 있는 제목 | 기존 전용 이모지 유지 |
| 캐시이동 제목 | 작은 별 사용, 블레어는 오른쪽 썸네일 |
| 큐브 관련 제목 | 기존 큐브 이모지를 일반 임베드 제목에 표시 (작은 author 제목으로 대체하지 않음) |
| 솔 에르다·솔 에르다 조각 등 재료·보상 | 본문의 의미 있는 전용 이모지 유지 |
| 전용 이모지가 없는 일반 제목 | 작은 금색 별 하나 사용 |
| 일반 공지·캐시샵 업데이트·판매 일정 | 기존 전용 제목 아이콘이 없다면 작은 별 사용 |
| 정상·점검 중 같은 상태 표시 | 상태를 구분하는 색·표시 유지 |

- 제목 이모지 뒤에는 일반 공백 한 칸을 사용합니다. 넓은 특수 공백은 넣지 않습니다.
- 한 제목에 전용 이모지와 별을 동시에 붙이지 않습니다.
- 작은 별: `<:ppojji_star_small:1548846409791574129>`.
- 별 원본과 등록 정보: [assets/emoji/README.md](../assets/emoji/README.md).
- 기존 이모지 ID는 `maple_bot.py`의 상수를 재사용합니다. 추측해서 새 ID를 쓰지 않습니다.
- 제목 도우미가 기존 전용 이모지를 무조건 제거하지 않는지 확인합니다.

- 캐시이동은 기간을 `:f` 타임스탬프로 시작·종료 한 줄씩 표시하며 요일은 생략합니다. 기간 아래에 시작 전에는 `시작: <t:시작:R>`, 시작 이후에는 `종료: <t:종료:R>`를 한 줄로 표시합니다. 참여 조건과 이동 방법은 짧게 정리합니다.

## 3. 색과 이미지

- 계산·일반 조회는 파랑, 캐시 시뮬레이터는 보라를 기본으로 합니다. 스스비·시그니처·원더베리는 예외로 기존 색(분홍·연보라·하늘색)을 유지합니다.
- 공지는 기존 카테고리 색을 유지합니다. 패치·알려진 이슈 추가 수정은 노랑입니다.
- 서버 상태 등 정상·오류의 의미가 있는 색은 유지합니다.
- 기존 공식 공지 이미지, 썬데이 배너, 랭킹 카드, 시뮬레이터 결과 이미지와 썸네일을 유지합니다.
- 양식 변경만을 위해 이미지 안의 글자·그래프·게임 UI를 다시 만들지 않습니다.
- 본문의 변경 전·후 글자에 색을 입히기 위한 코드 블록을 사용하지 않습니다.

## 4. 유형별 예시

아래 `<전용 이모지>`와 `<작은 별>`은 설명용 표기입니다. 실제 응답에는 등록된 이모지를 사용합니다.
수치는 양식 예시이며 계산값·일정·원문은 실행 시 확인된 데이터를 사용합니다.

### 계산 결과

```text
<HEXA 전용 이모지> HEXA 매트릭스 강화 계산
스킬 코어
Lv.0 → Lv.10

<솔 에르다 이모지> 솔 에르다　**30개**
<조각 이모지> 솔 에르다 조각　**680개**
```

입력 화면도 같은 제목·간격을 사용합니다. 미입력 항목은 `미입력`, 버닝 비활성 상태는 `미적용`으로 표시합니다. 드롭다운은 `하이퍼버닝: 적용`처럼 어떤 설정인지 알 수 있게 합니다.

### 시뮬레이터·기대값

- **스스비·시그니처·원더베리는 간결형 통일 대상에서 제외합니다.** 기존 영문 제목·이모지·색상과 하단의 `누적 횟수`, `지금까지 낭비한 돈`을 유지합니다. 기대값 버튼도 기존 텍스트 응답과 표현을 유지하고 별도 임베드로 바꾸지 않습니다. 아래 간결형 규칙은 이 세 명령어에 적용하지 않습니다.
- 결과 이미지와 아이템명·확률·기간 등 필요한 정보는 유지합니다.
- 누적 정보는 `이번 사용`, `누적 사용`, `누적 비용`으로 표시합니다.
- 기대값은 대상과 확률 뒤에 `평균 비용`, `평균 횟수`, `N회 내 획득 확률`을 간결하게 표시합니다.
- 비용 기준과 필요한 주의사항은 마지막에 짧게 둡니다.
- 재추첨·기대값 버튼, 소유자 제한, 응답 공개 범위는 바꾸지 않습니다.

### 일반 공지·캐시샵

```text
MapleStory | UPDATE
<작은 별> 공지 제목

• 주요 내용
• 주요 내용

[기존 공식 이미지]
```

기존 출처·카테고리 라벨, 원문 링크, 이미지와 색을 유지합니다. 확인되지 않은 번역 제목이나 요약 내용을 만들어 넣지 않습니다.

```text
<작은 별> 캐시샵 판매 일정

**진행 중**
**판매 종류**
시작: 날짜·시간
종료: 날짜·시간

**예정**
**판매 종류**
시작: 날짜·시간
종료: 날짜·시간
```

날짜는 Discord 타임스탬프로 표시합니다. 판매 종류와 기간만 보여주고 상세 상품 목록·외부 데이터마이닝 사이트 링크·`Commodity.img` 같은 내부 파일명은 넣지 않습니다. 예약 일정이 공식 확정 전 정보라는 안내는 짧게 유지합니다.

### 패치·알려진 이슈 추가 수정

```text
MapleStory | PATCH UPDATE
<작은 별> v.271 패치노트 추가 수정

**① 이벤트·아이템·미션 이름 · 수정 주제**
무엇에 관한 수정인지 짧은 맥락 설명

**변경 전:**
이전 내용

**변경 후:**
수정된 내용

**② 다른 수정 주제**
**추가:**
추가된 내용

공식 패치노트 확인
```

- 여러 항목은 ①·②·③으로 구분하며 항목별 장식 이모지는 쓰지 않습니다.
- 항목 제목과 맥락 설명은 붙입니다. 맥락과 비교 사이, 변경 전 내용 뒤, 번호 항목 사이, 원문 링크 앞에 빈 줄 하나를 둡니다.
- `변경 전:`·`변경 후:`·`추가:`·`삭제:` 라벨의 내용은 다음 줄에 둡니다.
- 추가에 가짜 변경 전 내용을 만들지 않습니다. 문서 안내 정정과 실제 게임 변경을 구분합니다.
- 별도 `핵심`·`패치` 필드를 반복하지 않고 원문 링크를 마지막에 둡니다.
- Known Issues 수정에도 같은 원칙을 적용하고 기존 전용 출처 라벨을 유지합니다.

## 5. 작업 시 확인

1. 해당 명령어의 기존 전용 이모지·이미지·버튼부터 확인합니다.
2. 제목·강조·간격을 맞추되 계산식·확률·수집·알림 조건은 양식 변경과 섞지 않습니다.
3. 이미지 전용 응답은 이미지 위에 짧은 제목을 붙일 수 있습니다. 복사용 코드 블록과 짧은 오류 안내를 억지로 임베드로 바꾸지 않습니다.
4. 제목 256자, 설명 4,096자, 필드 값 1,024자, 메시지 내 임베드 합계 6,000자 제한과 첨부 표시를 확인합니다. 긴 본문은 내용을 무작정 자르지 않고 나눕니다.
5. 사용자가 허용한 테스트 채널에서 실제 표시를 확인하고, 코드 수정·예시 게시·운영 배포 상태를 구분해 보고합니다.
6. 변경은 `CHANGELOG.md`에 기록합니다. 서버 배포 승인 원칙은 `PROJECT_RULES.md`를 따릅니다.
